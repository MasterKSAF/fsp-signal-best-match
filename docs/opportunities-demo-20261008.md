## API

- `GET /api/public/jobs/search` → `{items,total,page,pageSize,pageCount,exportLimit,applicationPolicy}`. Полная доступная опубликованная выборка; `pageSize` 1–100, default 20. `sort`: `newest`, `oldest`, `salary_desc`, `salary_asc`. Зарплатный фильтр пересекает вилку и нормализует период month/year; сортировка сравнивает месячную верхнюю границу. Налоги показаны отдельно.
- `skills` — JSON-array `[{"skill":"React","level":"Middle"}]`; без `level` не придумывается минимальный уровень. Совпадение названия точное без SQL→PostgreSQL. Для указанного minlevel в самой вакансии должно быть явное требование достаточного уровня. Обычные старые `skills` участвуют только в фильтре без minlevel.
- `resumeId` — конкретное своё резюме для объективного покрытия; кандидат с чужим/удалённым ID получает 404. Просмотр вакансий без подтверждённого общего грейда доступен. Текущая политика позволяет явно согласованный отклик с собственным резюме, требования работодателя не присваивают квалификацию.
- `GET /api/public/jobs/export?format=csv|xlsx` — тот же фильтр/порядок, все страницы; `X-Export-Row-Count`. Предел **10 000** показывается до скачивания; при превышении 422, файл не усечён молча. Проверяется повторно после чтения строк.
- `GET /api/me/applications/search` → `{items,total,page,pageSize,pageCount}`: q/company/title, status, resumeId, newest/oldest. Историческое выбранное резюме не подменяется `isPrimary`.
- `GET /api/me/invitations/search` → такой же envelope: q/company/title, status (в том числе `pending`=sent/viewed), resumeId, workFormat, newest/oldest.
- `GET /api/me/invitations/:id` — прямое конкретное приглашение с текущими правами и границей pool scope.

Старые array endpoints сохранены для совместимости. Старый `/public/jobs` оставляет ограничение 200; **новый интерфейс и экспорт используют `/public/jobs/search` и полную серверную выборку**, поэтому ограничения старого endpoint не обрезают поиск. По умолчанию новые публикационные таблицы выключены: `SIGNAL_WORKSPACE_ENABLED=true` включает отдельный стенд. Legacy company/jobs reads/writes при выключенном флаге не обращаются к новой таблице.

## Данные и миграция

`0012_job_discovery.sql` создаёт `signal_job_requirements`: отдельная необязательная локация и JSONB skill requirements. Существующие вакансии не переписываются. Создание/изменение вакансии обновляет эти значения атомарно с основной записью. Отсутствующие поля при старом PUT сохраняют текущие требования; удалённый skill удаляет его привязанный уровень. Любое редактирование увеличивает основную version, которая защищает отправку отклика.

Natural refresh работает только с перечисленными email основного/обзорного seed, `demoMode=true`, `reviewScopeId=null`, правильной ролью. Коллизия с ordinary/reviewer прекращает транзакцию. Имена реальных/ordinary/reviewer аккаунтов не меняются. Однократный marker защищает последующие пользовательские действия; existing резюме с пользовательским содержанием не переписываются. Результаты, даты попыток, рубрики и FSP-сведения не изменяются. Новые seed accounts получают естественные данные сразу. Значение demo qualification сохраняет своё историческое ограничение; новые skill certificates не сочиняются.

Операционная команда `scripts/refresh-natural-demo-profiles.ts` дополнительно жёстко ограничена проверенной БД `signal_independent_fixes_20261007`.

## Исправление формата приглашений после независимой проверки

Фильтр `workFormat` классифицирует явные форматы и их альтернативы целиком, вместо точного совпадения всей строки или поиска подстроки. «Удалённо или гибрид» подходит обоим фильтрам; одиночный формат — только своему. «Без удалённой работы» не означает удалённый формат. Явные исключения имеют приоритет над противоречащим разрешением. Неизвестные и условные описания, например «по договорённости» или «удалённо после испытательного срока», не получают придуманный формат; без фильтра такие приглашения остаются видимыми. Исходный текст условий сохраняется в ответе и БД.

Классификация охватывает всю доступную пользователю историю после остальных фильтров и до пагинации. Один набор разрешённых ID ограничивает и подсчёт, и выдачу страниц; лимит старого endpoint не применяется. Это консервативная грамматика явных условий, а не определение смысла произвольного текста.
