# Сверка реализации с ТЗ

**Историческая сверка до расширения банка и дополнительных модулей.** Описанные ниже ограничения и числа относятся к прежнему срезу. Текущая матрица: [completion-status.md](completion-status.md); техническое описание: [technical-description.md](technical-description.md).

Обновлено 5 октября 2026 года. Ниже разделены реализованный функционал, успешная приёмка сборки и работа перед подачей. Сводный протокол конкретной сборки хранится в `outputs/verification/final-report.json`.

## Закрытые функциональные пробелы

| Требование | Что реализовано | Граница реализации |
| --- | --- | --- |
| Резюме и профессиональный опрос | Опыт по местам работы, проекты, образование, портфолио, личные навыки; отрасль, специализация и шесть вопросов; рекомендация уровня и история до 20 завершённых редакций | Рекомендация по самооценке не подтверждает категорию. Распознавание загруженного файла не требуется при полноценном ручном вводе. |
| Выгрузка резюме | Прямое скачивание PDF, созданного сервером, со встроенными шрифтами и разделением заявленных и подтверждённых сведений | Личный экспорт не включает отдельные поля телефона/email и не раскрывает резюме работодателю. |
| Связь с ФСП ID | Собственный ID, согласие, состояния подключения, даты, достижения и контракт будущего адаптера | Реальный API не предоставлен: обычный ID ожидает проверки; демонстрационное достижение доступно только в Demo. Непроверенный ID не даёт бонус. |
| Тесты под несколько описаний ролей | Три профиля Backend / Python и программа по собственному приглашению; требования связаны с семействами задач; неизменяемый снимок программы | Четыре общих задания и два прикладных. Одна глубокая специализация, три категории. |
| Общая база кандидатов | Каталог работодателя без привязки к вакансии, фильтры и страницы по 24 профиля | Только видимые профили с согласием, подтверждённой категорией и тем же пулом. Контакты, полное резюме и опрос не выдаются. |
| Понятный интерфейс по ролям | Отдельные кабинеты, три темы, адаптивность, помощник, план подготовки, сравнение кандидатов и карта доказательств | Помощник даёт справочные подсказки. Выполнение плана подготовки само по себе не повышает категорию. |

Модель данных обновляется одной сгенерированной миграцией `0001_required_tz.sql`; snapshot и журнал Drizzle включены. Прежние данные и попытки v4 сохраняются.

## Подтверждённая приёмка

Прошли 34 из 34 автоматических тестов, проверка изоляции с отключённым Demo, сборка и запуск Docker. Сквозной HTTP-прогон против Docker на `127.0.0.1:4310` с origin `http://localhost:4310` завершился успешно: 23 из 23 групп. Детали — в [протоколе интеграции](../outputs/verification/integration.json); сводный отчёт — [final-report.json](../outputs/verification/final-report.json).

В браузере обычный кандидат прошёл шесть вопросов, сохранил опрос, получил рекомендацию Middle и скачал серверный PDF. Проверка «Надёжные сервисы» уровня Middle пройдена через интерфейс: ответы сохранены, отправлены и дали 100 баллов с подтверждением категории. Проверены Demo-вход работодателя, каталог и фильтры, индикаторы режима и отключение анимации. Это автоматизированный контроль на синтетических данных, не независимая оценка кандидатов и не человеческий пилот.

Техническое описание обновлено до шести страниц; все страницы PDF визуально проверены. Презентация и видео ещё относятся к предыдущей версии.

## Ограничения, которые нужно честно назвать

- Официальный реестр ФСП не подключён; готова привязка ID и предусмотрен контракт адаптера.
- Рабочий банк охватывает Backend / Python и уровни Junior, Middle, Senior. Frontend и Data не выдаются за готовые программы.
- Сравнение 900 форм подтверждает общую структуру, шкалу и совпадение четырёх общих заданий. Оно не доказывает одинаковую сложность для людей.
- Метки контроля подбора синтетические. Независимой оценки качества найма и завершённого человеческого пилота нет.
- Локальный Mailpit не доставляет внешние письма. Публичное развёртывание требует HTTPS, реальной почты и подходящего хранения данных.
