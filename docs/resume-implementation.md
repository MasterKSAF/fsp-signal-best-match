# Структурированное резюме, первичный опрос и PDF

Реализовано 05.10.2026 для обязательного кандидатского сценария. Самооценка и сведения кандидата отделены от подтверждённой тестированием категории.

## Возможности

- Резюме сохраняется в PostgreSQL и загружается при повторном входе: описание, личные навыки, до 10 мест работы, 10 проектов, 5 записей об образовании и 8 ссылок.
- Для каждой записи опыта есть компания, должность, период и достижения. Поддерживаются текущая работа, незавершённое обучение, учебные проекты и кандидат без опыта.
- Специализированный первичный опрос содержит отрасль и специализацию Backend / Python, шесть вопросов: Python, базы данных, API, тестирование, надёжность и самостоятельность. Незаполненный опрос можно сохранить и продолжить позже.
- Завершённый опрос рекомендует исходную сложность, но пользователь сам выбирает Junior / Middle / Senior на странице проверки. Рекомендация не меняет подтверждённую категорию или навыки.
- До 20 последних изменённых завершённых опросов хранятся как неизменяемые снимки с датой и рекомендацией. Повторное сохранение одинакового опроса не создаёт дубликат. При частичном редактировании прежняя история сохраняется, но для новой попытки нужен завершённый **текущий** опрос.
- PDF скачивается непосредственно из приложения, без окна печати. Включает сохранённый основной профиль, структурированное резюме, подтверждённые/заявленные навыки и текущую самооценку. Есть встроенные русские шрифты, переносы между страницами, номера страниц и дата формирования.
- Поля телефона и почты исключены из PDF. Произвольный текст и ссылки кандидат добавляет сам и должен проверять перед самостоятельной публикацией файла.

## API и подключение

- `GET /api/me/resume`: собственное резюме или пустой шаблон, вопросы, шкала, рекомендация, история.
- `PUT /api/me/resume`: атомарное сохранение собственного резюме; серверная валидация ограничений и периодов; завершённые изменённые ответы добавляются в историю.
- `GET /api/me/resume/pdf`: скачивание только своего резюме, `application/pdf`, `Content-Disposition: attachment`, `Cache-Control: no-store, private`.
- Все три эндпоинта требуют сессию кандидата; отсутствуют параметры доступа по чужому userId. Роль работодателя получает 403, неавторизованный запрос — 401.
- Таблица `signal_candidate_resumes` добавляется миграцией `0001_required_tz.sql`. Она не изменяет и не удаляет прежние профили, тесты или приглашения. `user_id` — FK с каскадным удалением для удаления аккаунта.
- Экспорт таблицы: `signalCandidateResumesTable`. Router default export: `artifacts/api-server/src/routes/signal-resume.ts`.
- Компонент `CandidateResumeSection` размещается после основной формы профиля. CSS использует темы приложения, раскладка перестраивается на мобильной ширине.
- Helper `getCandidateQuestionnaireStatus(userId)` возвращает `completed`, `recommendedGrade`, `industry`, `specialization`. Проверка завершения используется в серверном сценарии старта теста; прошлый снимок не заменяет незавершённый текущий опрос.
- OpenAPI-фрагмент: `docs/contracts/resume-openapi.yaml`.

## Правило рекомендации

Каждый ответ — самооценка 0–3: не работал; решаю с помощью; самостоятельная работа; проектирую и помогаю другим.

До получения всех шести ответов рекомендация отсутствует. Senior рекомендуется при сумме от 15, всех ответах от 2 и самостоятельности 3. Middle — при сумме от 9, Python от 2 и отсутствии нулевых ответов. Иначе рекомендуется Junior. Это явная эвристика выбора первой проверки, не статистически валидированная шкала и не доказательство компетентности.

Специализация опроса пока одна — Backend / Python. Название отрасли сохраняется как профессиональный контекст; вопросы проверяют самооценку общих компетенций этой специализации, а не отраслевое регулирование. Сам опрос не является системой автоматического найма.

## Проверка

- `tests/resume-contract.test.ts`: пять тестов — структурированный русскоязычный профиль, запрет опасных URL/обратных периодов/подмены категории, незавершённый опрос и пробелы в базовых навыках, идемпотентная история после перестановки ключей PostgreSQL JSONB, многостраничный PDF со встроенным шрифтом.
- TypeScript: библиотеки, API и web прошли проверку типов.
- Рендер PDF проверен визуально: реалистичный профиль — 2 страницы; длинное резюме с 10 местами работы — 8 страниц. Кириллица извлекается корректно, пустых страниц с одним колонтитулом нет, нумерация совпадает с количеством страниц.
- Проверочные файлы (с вымышленными данными): `outputs/verification/resume/resume-preview.pdf`, `resume-long-preview.pdf`; изображения `final-1.png`, `final-2.png`, `long-2.png`, `long-8.png`.
- Проверка HTTP-изоляции между пользователями и общая браузерная проверка выполняются в интеграционном прогоне основного приложения.

## Шрифты и сборка

PDFKit 0.17.2 — runtime dependency API, `@types/pdfkit` — dev dependency. PDFKit исключён из esbuild bundling, чтобы сохранить доступ к собственным ресурсам пакета. Локальные Manrope Regular/SemiBold вместе с OFL находятся в `artifacts/api-server/assets/fonts` и входят в контейнер и архив исходников. Они получены из уже используемого проектом Manrope Variable, сетевые запросы для экспорта не требуются.
