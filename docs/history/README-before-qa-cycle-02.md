# Signal

Подбор IT-специалистов по подтверждённым навыкам и условиям работы. Конкурсный прототип специального трека ФСП, команда Best Match.

Текущая версия исходников — **0.4.1**; программы `signal-backend-python-v6` и `signal-frontend-typescript-v2`, алгоритм `fsp-signal-match-v5`. Общие факторы потребности и сопоставимые очереди описаны в [matching-v5.md](docs/matching-v5.md). Новые проверки Senior требуют полного решения архитектурного критерия; пороги Junior 67 и Middle/Senior 83 сохранены. Ранее выданные попытки оцениваются по своему неизменяемому снимку, включая прежние версии банка.

Комплект в outputs/submission относится к предыдущему принятому выпуску 0.4.0 / match-v4. Его медиа и архив обновляются после независимой приёмки QA-цикла, а старые измерения не переименовываются в результаты новой сборки. Текущий статус фиксирует [qa-cycle-01.json](outputs/verification/qa-cycle-01.json).

## Запуск из исходников

Требуются Node.js 24, pnpm 11.25.0 и Docker Compose. Команды выполняются из корня проекта.

```powershell
node scripts/setup-env.mjs
pnpm install --frozen-lockfile
docker compose up -d db mail
pnpm db:migrate
pnpm db:seed
pnpm dev
```

Веб: http://127.0.0.1:4310, API разработки: 4312, PostgreSQL: 55433, Mailpit: http://127.0.0.1:8026.

Полностью контейнерный вариант (без локального pnpm install):

```powershell
node scripts/setup-env.mjs
docker compose --profile full up -d --build
```

Перед ним остановите pnpm dev, использующий тот же порт. Контейнер применяет миграции и синтетический seed; первый запуск занимает несколько минут. Готовность: GET /api/healthz. Именованный том БД сохраняется при docker compose down. Не используйте down --volumes для рабочего стенда. Этот Compose предназначен для локального показа: Demo и Mailpit заданы в его конфигурации. Для внешнего запуска их нужно явно переопределить, как описано в [инструкции](docs/deployment.md).

## Вход и Demo

Нажмите «Вход» справа вверху. В модальном окне выберите роль. Обычная регистрация требует подтверждения email; локальный код приходит в Mailpit и не отправляется внешнему адресату.

Переключатель Demo находится внутри формы. Он подставляет демонстрационные реквизиты для выбранной роли; «Войти» создаёт отдельную серверную Demo-сессию. Это синтетические профили, а не обычный аккаунт. В кабинете жёлтый индикатор обозначает Demo, зелёный — обычный режим; красный — недоступность API. Наведение показывает пояснение. DEMO_MODE=false отключает Demo-вход и выдачу демонстрационных данных обычным пользователям.

Для повторного показа pnpm demo:reset пересоздаёт только синтетический пул. Он сохраняет обычные аккаунты, но сбрасывает накопленные действия Demo; после сброса войдите заново. Не запускайте без необходимости.

## Функциональность

- Две роли, email-код, серверные сессии, ограничения запросов и проверка прав.
- Профиль, структурированное резюме, история профессионального опроса и PDF.
- Backend / Python и Frontend / TypeScript: Junior, Middle, Senior; индивидуальные формы, серверный таймер, частичный зачёт, история и план развития.
- Версионируемый банк: 72 семантических шаблона; управление отключением/возвратом, аудит и аннулирование ошибочной попытки без изменения её исходного снимка.
- Каталог навыков, карта покрытия требований, банк доступных кандидатов, объяснимый подбор, происхождение доказательств и сравнение двух профилей.
- Приглашения с зарплатой и условиями: просмотр, принятие, отказ, адресное согласие и отзыв контактов.
- Публичные вакансии и отклики с неизменяемым снимком условий и отдельным согласием.
- Учебные задания компаний: подписки, предпочтения, регулярная выдача, общий недельный лимит, ответы, проверка и отдельные свидетельства.
- Изолированный A/B-пилот: согласие и срок хранения, замороженные формы, независимые группы и две экспертные разметки, отзыв, безопасные выгрузки и отчёт.
- Светлая/тёмная/системная темы, компактная главная, закреплённая шапка, кнопка «Назад», живой текстовый бренд, сезонный фон и контекстный помощник.

## Проверки и воспроизводимость

```powershell
pnpm build
pnpm test
pnpm quality:evaluate
node --import tsx scripts/evaluate-competitive-matching.ts
$env:INTEGRATION_API_ORIGIN = 'http://127.0.0.1:4310'
$env:INTEGRATION_APP_ORIGIN = 'http://127.0.0.1:4310'
$env:INTEGRATION_MAILPIT_ORIGIN = 'http://127.0.0.1:8026'
$env:INTEGRATION_DOCKER_CONTAINER = 'fsp-signal-app-1'
pnpm test:integration
node --env-file-if-exists=.env --import tsx scripts/matching-integration-test.ts
node --env-file-if-exists=.env --import tsx scripts/integration-assessment-managed.ts
node --env-file-if-exists=.env --import tsx scripts/opportunities-integration.ts
node --env-file-if-exists=.env --import tsx scripts/research-integration.ts
pnpm test:production
```

Текущий прогон: **72 модульных теста**, typecheck, **50 групп на Docker HTTP** (23 общих + 12 возможностей + 5 подбора + 10 управляемого банка), **7 отдельных research HTTP-групп**, **4 production isolation** и **4 группы CLI пилота**. Research, production isolation и CLI используют отдельные локальные HTTP-процессы; их не следует выдавать за запросы к Docker. CLI приведён отдельно и не прибавлен повторно к 57 основным HTTP-группам.

Доказательства: [локальные тесты](outputs/verification/final-tests-local-refinement.json), [HTTP и происхождение проверок](outputs/verification/final-http-refinement.json), [текущая сборка](outputs/verification/release-current-build.json), [матрица требований](docs/completion-status.md). HTTP проверен на предшествующем образе; 57 зафиксированных исходных входов production API/БД/схемы/lockfile совпадают с текущим контейнером. Бинарная идентичность скомпилированных API bundles не измерена. Финальная проверка интерфейса относится к текущему образу и сохраняется отдельно в `outputs/verification/mobile-refinement.json`. Старые `final-report.json`, `final-http-docker.json`, `final-ui.json` описывают прежний срез.

HTTP-проверки требуют локальные PostgreSQL и Mailpit; создают собственные синтетические записи и удаляют только их. Локальный тестовый процесс читает oracle для проверки положительного пути; публичного HTTP-доступа к ключам нет. Независимые эталоны для проверки уровней и их ограничения описаны в [валидации грейдов](docs/assessment-validation.md). Для повторения технических проверок пилота: `node --env-file-if-exists=.env --import tsx scripts/pilot-cli-integration.ts`.

Текущий нагрузочный профиль: [эксплуатационные проверки](docs/operations-refinement.md#новый-профиль-нагрузки). Команда `node --env-file-if-exists=.env --import tsx scripts/load-scale.ts`: 1000 связанных синтетических профилей, 16 работодателей, 32 сессии, 30 секунд прогрева и 180 секунд измерения. Итог и заранее заданные лимиты читаются из `outputs/verification/load-scale.json`; наличие скрипта или preflight не означает успешное измерение. Старый [профиль 24 сессий](docs/load-profile.md) сохранён как история. Локальная нагрузка не является заявлением о производственной ёмкости.

Сборка исходного ZIP: `python scripts/package-source.py` (без записи: `--check-only`). Проверка с нуля: `pwsh -NoProfile -File scripts/clean-source-launch.ps1 -ExpectedSha256 <SHA256>` с хешем запечатанного ZIP. Она использует отдельные порты, случайно названный Compose project, новую БД и установку зависимостей без кэша; проверяет текущие программы, Senior policy и metadata подбора. Аудит приватности **того же ZIP**: `python scripts/audit-source-privacy.py --expected-sha256 <SHA256>`; он выводит только количества, хеши и категории, без секретов и текста обнаружений. Затем выполняются `python scripts/finalize-release.py` и `python scripts/package-submission.py --reuse-tested-source`. Финализатор связывает текущие технические и медиа-аудиты с SHA файлов и сохраняет `final-report-refinement.json`; сборка полного комплекта не пересоздаёт исходный ZIP. Прежние архивы сохраняются в `outputs/submission/history/`.

OpenAPI: lib/api-spec/openapi.yaml и GET /api/openapi.yaml. При правке фрагментов: node scripts/merge-completion-contracts.mjs, затем pnpm codegen.

## Границы и внешние шаги

Контрольные метрики и технические тесты используют синтетические данные. Они не подтверждают точность найма, человеческую валидность уровней или равную сложность форм для людей. Пакет [пилота на 36 добровольцах](docs/pilot/operator-guide.md) готов: согласие, AB/BA, независимый предварительный профиль, слепые пакеты и импорт. Человеческие результаты и самостоятельное прохождение новыми пользователями остаются `not_measured`. Два внешних эксперта могут усилить доказательства; это не универсальное формальное условие ТЗ.

ФСП не предоставила интеграционный API этому стенду. Обычный ID ожидает проверки и не даёт выдуманных достижений. Только Demo показывает явно синтетическую историю. Бонус ФСП не обходит обязательные требования.

SMTP-адаптер реализован и проверен с локальным SMTP-сервером. Внешний провайдер, домен и доставка пока не подключены. Для публичного развёртывания нужны HTTPS, отдельная БД, секреты и резервное копирование. ATS и защита от поддельных данных описаны как архитектура; действующая внешняя ATS-интеграция, прокторинг и проверка личности не заявляются.

Адреса `127.0.0.1`/`localhost` доступны только на компьютере запуска. Они не заменяют ссылки, доступные жюри. Ссылка на опубликованные исходники, внешняя ссылка на видео и фактическая подача в личном кабинете должны быть подготовлены и проверены отдельно; локальный ZIP сам по себе не означает публикацию или сдачу. Публичный сервер — возможный дополнительный способ показа, его наличие здесь не заявляется.

В исследовательский режим оператор попадает только при явном назначении SIGNAL_RESEARCH_OPERATOR_IDS. Обычный участник работает по приглашению, а исследовательские ответы не повышают категорию профиля.
