# 1. Функциональная и компонентная архитектура

Браузерный React-клиент обращается к Express API. API проверяет сессию, роль, владельца, scope, текущее состояние и согласие. PostgreSQL хранит документы, неизменные контексты попыток/предложений, результаты и разрешения. Drizzle применяет версионированные миграции. Фронтенд не выставляет грейд и не выбирает серверный scope.

| Компонент | Ответственность |
| --- | --- |
| Вход и сессии | Подтверждение email, ordinary/overview/reviewer-пулы, cookie, серверные роли |
| Резюме и опрос | До пяти профессиональных документов, ревизия, явный выбор, отдельные согласия |
| Квалификационный экзамен | Управляемый банк, выдача формы, сохранение, scorer и correction |
| Общий квалификатор | Применимость исходных доказательств, грейд/навыки конкретного документа |
| Каталог и подбор | Фильтры, дедупликация людей, полный порядок, объяснение и сравнение |
| Приглашения/вакансии | Условия, снимок выбранного документа, адресное раскрытие контактов |
| Практика компании | Рубрика, резюме/ревизия/контекст, подписка, ответ и отдельная оценка |
| Доверие | Блокировка, жалоба, ограничения, апелляции, аудируемое право модератора |

Имя, фото и контакты — свойства аккаунта. Профессиональные данные — свойства выбранного резюме. Копия закрыта по умолчанию и не копирует чужой грейд между программами. Основной документ используется только документированными legacy-маршрутами без ID; новые действия передают явный resumeId. Нет случайного выбора первого документа.

Ревизия защищает от перезаписи из другой вкладки: 409 сохраняет локальный черновик. Удаление — tombstone, а не стирание истории экзамена. После удаления всех документов GET не восстанавливает прежнее резюме. Лимит пяти и назначение основного сериализуются блокировкой владельца.

### Данные, безопасность и доверие

Сессия содержит хеш случайного токена; пароль — scrypt. Cookie HttpOnly/SameSite=Strict, Secure при HTTPS. Изменяющие запросы проверяют Origin. ID ограничены int32. Экзаменационные ответы/oracles, контактные поля и серверный pool digest не входят в employer DTO.

Контакт открывается только конкретной компании после адресного согласия. Отзыв и блокировка прекращают доступ; разблокировка не восстанавливает прежний grant. Модератор — отдельная административно выданная способность, не вариант публичной регистрации. Автор жалобы и её закрытый текст не раскрываются работодателю.

Reviewer-пары получают собственный UUID scope. Overview имеет demoMode=true/null scope, ordinary — false/null, reviewer — true/UUID. Все внешние выборки требуют полного совпадения пула. Сессия аннулируется при изменении принадлежности аккаунта. Reviewer не получает послаблений экзамена или право модератора.

# 2. Механика проверки и устойчивость к распространению

Кандидат выбирает конкретный документ, завершает первичный опрос, выбирает и явно подтверждает грейд. Назначение `signal_qualification`, программа, версия, resumeId, направление, заявленный уровень и контекст фиксируются сервером. Клиент не может изменить purpose/version чужой попытки. В контексте приглашения уровень вакансии хранится отдельно от выбранного кандидатом экзаменационного уровня.

Активны Backend/Python v6 и Frontend/TypeScript v2, три грейда. Каждая программа проверяет шесть компетенций, по два содержательных шаблона на компетенцию/уровень — 72 записи банка. Параметры и порядок вариантов создают формы, но не новые независимые компетенции. Подробная карта — assessment-managed.md.

| Программа | Содержательные примеры |
| --- | --- |
| Backend/Python | API/replay, SQL/tenant и отсутствующие связи, диагностика, идемпотентность, архитектура изменений, перенос условий |
| Frontend/TypeScript | Асинхронное состояние, преобразование данных, диагностика интерфейса, клавиатурная доступность, архитектура, изменение условий |

Срок формы — 45 минут. Порог Junior/Middle/Senior — 67/83/83. Критичные критерии требуют 100: у Junior/Middle три, у текущих Senior четыре, включая архитектуру. Прежние v5/v1 и Backend v4 читаются по своим исходным снимкам и рубрикам, без скрытого изменения решения.

Выдача учитывает экспозицию и ранее встречавшиеся шаблоны. Оператор может отключить дефектный шаблон с причиной и аудитом; новые формы его не используют, активные сохраняют выданные условия. Недостаточное покрытие возвращает 503 вместо облегчённой выдуманной формы. Correction отзывает источник явно, сохраняя прежний результат.

Повтор ограничен 7 днями, повышение уровня — 90 днями. Копирование/смена основного документа не обходят эти сроки. Неуспех не понижает прежний грейд принудительно, более поздняя слабая попытка не освежает старый сильный результат. Таймеры идут по реальному времени, независимо от настройки движения интерфейса.

# Подтверждения и задания компании

### Общие подтверждения и применимость

«Мои подтверждения» — история аккаунта, а не копия экзаменов каждого резюме. Уникальный источник — попытка + критерий + канонический навык. Видны исходная дата, версия, проверенный критерий и уровень критерия, выбранные применения и причины неприменения.

Матрица `signal-evidence-compatibility-v1` содержит 90 явных identity-правил для пяти известных версий и трёх уровней. Сейчас нет содержательно обоснованных общих критериев Backend↔Frontend. SQL сохраняется в аккаунте, но не становится проверенным Frontend-навыком; Python не приравнивается к TypeScript. Неподдерживаемый критерий/версия даёт отказ с объяснением, а не fuzzy-перенос.

Пять резюме используют один источник с прежней датой. Удаление исходного документа сохраняет источник; correction прекращает его применения во всех документах. Исторические агрегаты без полной версии/критерия обозначены ограничением, не превращаются в выдуманные individual proofs. Уровень отдельного успешного критерия не означает грейд всей программы.

### Практика компании

`company_task` имеет отдельную рубрику, цель и источник оценки. Компания выбирает конкретное допустимое резюме; предложение и подписка сохраняют его ID/ревизию и безопасный контекст. Смена основного не переносит задание. Скрытие, удаление, смена направления, отзыв разрешения или потеря квалификации прекращают новые действия; исторические условия и результат сохраняются.

Миграция 0009 помечает прежнюю практику без снимка `legacy_unbound`, не подставляет нынешний основной документ. Новый ответ/предложение требует явной корректной привязки. Оценка компании не меняет категорию Signal, даже при 100/100.

# 3. Подбор и категоризация

Категория — специализация плюс подтверждённый грейд. Каталог допускает опубликованные согласившиеся документы без грейда и показывает «Грейд не подтверждён» с дальнейшим шагом. Строгий подбор требует квалификации не ниже минимума, обязательных подтверждённых навыков и всех условий доступа.

Фильтры AND относятся к одному целому резюме: направление, грейд, все выбранные навыки, опыт, формат, сопоставимая зарплата, доступное фото, готовность и давность. Нельзя собрать React из одного документа и SQL из другого для прохождения фильтра. После фильтров выбирается один целый документ человека; затем total и страницы по 24.

Без потребности подтверждённые документы идут первыми. Из реально проходящих фильтры альтернатив человек представляется подтверждённым документом, если такой есть. В смешанных несопоставимых категориях порядок нейтральный; неподтверждённый остаётся видимым без придуманного Junior. Фото, количество документов и готовность не дают квалификационных баллов.

### Соответствие потребности

| Фактор | Вес при известной зарплате |
| --- | --- |
| Подтверждённые обязательные/желательные навыки | 62,5% |
| Формат работы | 18,75% |
| Совместимые зарплатные условия | 12,5% |
| Давность свидетельства | 6,25% |

Неизвестная зарплата исключается из суммы, известные веса перенормируются. Год переводится в месяц только при совпадающей gross/net базе. Давность: до 30 дней — 1, до 90 — 2/3, менее 180 — 1/3, далее/неизвестно — 0. Это политика проекта, не измеренная скорость утраты человеческого навыка.

# Порядок категорий и свежесть подбора

Порядок `need-fit-proof-category-queues-v3`: сначала need-fit и полнота происхождения. В равном tier категории получают нейтральные якоря по минимальному NFC-псевдониму/ID всех участников **до** внутренней сортировки. Целые category-блоки не меняют порядок из-за ФСП, rawScore или добавления Senior-бонуса.

Внутри категории сохраняются сопоставимые очереди программы/версии/рубрики; сырые оценки сравниваются только в своей очереди. Ограниченный ФСП-сигнал влияет внутри категории. Между Middle/Senior или v5/v6 нет измеренной общей шкалы. Справочное число score не заменяет реальную позицию полного пула.

Объяснение показывает конкретный документ, условия и происхождение, а парное сравнение использует позиции в том же полном пуле. Пара не перестраивает рейтинг; два резюме одного человека не занимают два места. Приглашение сохраняет выбранный document snapshot и действующие условия.

### Свежесть и производительность

Ключи кешей проверяют свежие полные подписи документов и текущие identity/scope/видимость/согласия/ФСП-связь. Текущие исправления и статус оценки перечитываются; TTL не подменяет проверку разрешений. Очередь сборки больших снимков ограничивает одновременное декодирование. Неизменные проекции защищены; чтение даты выдаёт новый Date, а собственный пользовательский reader не получает внутренний shortcut.

Кеши не содержат разрешения открывать контакты. Любое действие заново проверяет владельца и текущий доступ. [Полная нагрузка 0.6](../outputs/verification/0.6.0/multi-resume/load-comparison-1320e58d7650.json) относится к точной обычной API-сборке `e72fc99a…` и неизменным 910 canonical источникам/11 assets. Кеш-бюджеты 128+14+48 MiB — оценка удержания, не строгий лимит heap и не разрешение хранить устаревший доступ.

Проверки разделены по предмету: scorer, применимость источников, формула/порядок подбора, ACL, настоящий HTTP, браузер, фиксированная нагрузка, чистый запуск ZIP. Один PASS не подменяет другой, а число повторных групп не суммируется в «новую точность».

На изолированном source API 4363 реестр прошёл 11 HTTP-групп: один источник в пяти копиях; независимые программы; частичный критерий без грейда; смена/удаление исходного документа; ограничения повторов; свои профессиональные значения после перечитывания; отзыв после прежних чтений; владение и отсутствие ответов/oracles/контактов. Три собственных аккаунта удалены. Отдельно 22 unit-контроля квалификации/назначения/реестра прошли без skip. Практика с явным документом прошла 16 HTTP-групп со своей уборкой.

Фикстуры убраны по собственным ID. 222 обзорных аккаунта/220 резюме отдельно синтетические, не независимые reviewer. [Браузерный протокол](browser-acceptance-0.6.0.md) относится к source UI с теми же reviewed исходниками, а не выдаётся за compiled GUI или исследование людей.

# Оценка качества и границы переноса

### Содержательная оценка и перенос

Историческая валидация 6 октября подготовлена на собственной синтетической рубрике с помощью ИИ: 36 форм, 216 независимо разобранных заданий, 468 сконструированных работ. Найденный Senior-пробел исправлен требованием архитектуры; на том фиксированном наборе расхождения 12/468→0/468. Это устранение конкретного дефекта, не 100% классификация реальных специалистов. A/B решения совпали 216/234; все 18 различий сохранены.

Ограниченный source-mechanism transfer-v4 исследует перенос записанного метода на поддерживаемый синтаксис. Неподдерживаемые определения и изменённый значимый синтаксис дают not_evaluated. Готовые ответы и освоение метода различаются на сконструированных сценариях; это не измерение всех стратегий ИИ/внешней помощи и не опыт обучения людей.

Протокол дополнительной подтверждающей формы заморожен до результатов. В 17 синтетических эпизодах сохранены лишнее срабатывание после обучения и пропущенная неопределённость на границе. Банк имеет только две содержательные формы на компетенцию: третья может иметь новые параметры без нового template. Production-правило автоматически не включено. # 5. Предполагаемая интеграция с ФСП

Настоящий реестр/API ФСП на хакатоне не предоставлен. Реализованы адаптер, согласие, отображение provenance и безопасная деградация. Локальный `signal-fsp-example-v2` содержит только `synthetic_fixture`; обычный аккаунт не может импортировать такую историю как настоящую.

Номер ФСП — заявка на связывание, а не доказательство. Legacy-флаг и неизвестное место не дают бонуса. Плохой тип поля, несовпадающий ID/провайдер, невалидная дата, отзыв согласия или ошибка связи не превращаются в подтверждённое достижение.

### Политика спортивных результатов

`fsp-category-results-v1`: подтверждённое участие — 1, призовое место — 2, победа — 3; берётся **максимум**, не сумма повторов. Это выбранная командой формула. ФСП не повышает грейд, не создаёт обязательный навык и не открывает чужой пул/контакты. Он влияет только внутри категории после общего fit и полноты доказательств.

Для настоящего подключения нужны предоставленный server API, проверяемая связь личности, согласие, правила обновления/отзыва и маппинг действительных спортивных результатов. Нельзя представлять существующий synthetic adapter официальным подключением. Формула проекта не выдается за правило Федерации о спортивных разрядах.

# 6. Описание API

Контракт — OpenAPI 3.1 в `lib/api-spec/openapi.yaml`, DTO/React-клиент генерируются из него. Любое новое поле сверяется с backend, а наличие схемы не означает, что endpoint допускает чужой ID.

| Группа | Основные операции |
| --- | --- |
| Доступ | Регистрация, локальное подтверждение, вход/выход, текущая сессия, отдельный overview Demo |
| Резюме | Список/создание/копия, явный документ, ревизия, основной, скрытие/удаление, фото и PDF |
| Квалификация | Подготовка, начало с явной целью/уровнем, сохранение, отправка, история и результат |
| Подтверждения | Прежний паспорт `/me/evidence?resumeId=…`; новый общий `/me/evidence/registry` |
| Справочник | `/dictionaries/skills`: канонические ID, labels, aliases и покрытие программ |
| Компания | Потребности, каталог, полный подбор, объяснение/сравнение, приглашения/вакансии |
| Практика | Шаблон, допустимые конкретные резюме, подписка/предложение, ответ/оценка/отзыв |
| Доверие | Блок/жалоба, очередь и решение модератора, ограничение и апелляция |

Реестр доступен только текущему кандидату-владельцу и не принимает query selectors. Read-only repeatable-read транзакция согласует источники, corrections и документы. Ответ содержит matrixVersion, исходные criteria и applications с reason/nextStep; не содержит ответы, oracles, оператора, фото, контакты или digest.

Приглашения требуют resumeId и idempotency key. Повтор одного намерения возвращает прежний lifecycle, изменение body под тем же ключом — 409. Лимит компании по умолчанию 20 за скользящие 24 часа; закрытое отношение company/person имеет 7-дневный cooldown. Блокировка/модераторское ограничение проверяются и при выдаче контактов, и при действиях практики.

PDF экспортирует выбранный документ, разделяет заявленные и проверенные сведения. Контактные поля аккаунта не добавляются; свободный текст и ссылки сохраняются как указал кандидат. Это не обещание удаления любого email/телефона из авторского текста.
