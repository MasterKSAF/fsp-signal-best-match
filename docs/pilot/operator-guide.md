# Готовый малый пилот Signal

## Цель и размер

Первый этап: 36 добровольцев, 18 Backend и 18 Frontend; по 6 с исходной независимой оценкой Junior/Middle/Senior на программу. Все проходят **целевой Middle**, две формы A/B. Внутри каждой исходной группы организуйте последовательное вступление парами: один AB, другой BA; сервер назначает их автоматически. Получатся 3 AB + 3 BA в каждой группе, 18 пар на программу. Не меняйте уже выданный сервером порядок и не включайте отказавшегося человека ради баланса.

Цель — обнаружить непонятные условия, существенные переходы решения и практические проблемы; получить описательный сигнал разделения групп на пороге Middle. Это не калибровка населения и не доказательство всех Junior/Middle/Senior границ. При 18/18 совпадениях нижняя граница двустороннего 95% Wilson-интервала около 82,4%; нулевые расхождения такой малой выборки не доказывают 100% стабильность. Шесть человек в группе дают широкую неопределённость; p-value, IRT и нормативы рынка в этом пилоте не заявлять.

После первого этапа при наличии участников: отдельно создать Junior и Senior исследования обеих программ по той же структуре (ещё 72 человек; всего 108, либо заранее согласованные повторные участники с явной зависимостью измерений). До этого человеческая сложность и пороги Junior/Senior остаются `not_measured`. Не переносить показатели Middle на остальные уровни.

## До набора

1. Заполнить `consent-and-operator-record.md`, заморозить методику, условия и версии `signal-backend-python-v6`/`signal-frontend-typescript-v2`, шестикритериальные рубрики и 67/83; зафиксировать SHA файлов. После результатов не изменять пороги этого исследования.
2. Ответственный администратор локального стенда назначает подтверждённый личный аккаунт оператора через `SIGNAL_RESEARCH_OPERATOR_IDS`; роль работодателя не даёт доступ сама. Оператор входит в `/research`. Cookie не передавать людям, не помещать в исходники/публичные команды.
3. Создать два исследования из подготовленных JSON. Сервер замораживает реальные снимки форм; сохранить пустой `/aggregate-report` и список состава/версий. Метка `operator_declared_human` — заявление оператора, пока наблюдений нет отчёт остаётся `not_measured`.
4. Набор и приглашения организует пользователь после отдельного решения: этот пакет никому не отправляет сообщения. Участник добровольно принимает `research-consent-v1` на странице исследования. Исходная работа и оценка делаются до форм, по `independent-pretest-rubric.md`, затем оператор фиксирует группу через API. Без группы форму не начать; после начала изменить её нельзя.

## Проведение

Раздайте `participant-instructions.md` без ответов и подсказок. Для всех один компьютер/сопоставимые устройства, тихое место, 45 минут максимум на форму, одинаковый 10-минутный перерыв; фиксируйте отклонения. Оператор помогает только с техническим доступом. Внешняя помощь/сбой/перерыв регистрируются, наблюдения не удаляются ради улучшения метрик. Неполные пары остаются в отчёте; знаменатель A/B — только полные пары, численность отказов/неполных отдельно.

После закрытия сбора получите два слепых пакета через `/review-packet`; вложите только разрешённые обезличенные исходные работы с теми же кодами. В packet нет Signal-score, формы, исходной группы и мнения коллеги; сами не дописывайте их. Каждый оценщик самостоятельно заполняет свой `reviewerId`, `grade`, `comment`. Не используйте один и тот же авторский код для двух людей. API принимает ровно два полных исходных файла и сохраняет разногласия. Если внешних оценщиков пока нет, это `not_measured`; не заполняйте их выдуманными людьми.

## Команды импорта и отчёта

Все команды из корня проекта, PowerShell 7. Cookie единственной сессии оператора хранится в `outputs/local-backup/pilot/session.txt`; внешние материалы и результаты также только в этой приватной папке, исключённой из поставки. Сайт позволяет выполнить те же шаги без CLI.

```powershell
node --import tsx scripts/research-pilot.ts --self-test
node --import tsx scripts/research-pilot.ts create --input docs/pilot/study-backend-middle.json
node --import tsx scripts/research-pilot.ts create --input docs/pilot/study-frontend-middle.json
node --import tsx scripts/research-pilot.ts group --study 1 --enrollment 1 --grade Middle --basis-file outputs/local-backup/pilot/basis-001.txt
node --import tsx scripts/research-pilot.ts close --study 1
node --import tsx scripts/research-pilot.ts packet --study 1 --reviewer reviewer-one --out outputs/local-backup/pilot/reviewer-one.json
node --import tsx scripts/research-pilot.ts packet --study 1 --reviewer reviewer-two --out outputs/local-backup/pilot/reviewer-two.json
node --import tsx scripts/research-pilot.ts import --study 1 --input outputs/local-backup/pilot/reviewer-one.json
node --import tsx scripts/research-pilot.ts import --study 1 --input outputs/local-backup/pilot/reviewer-two.json
node --import tsx scripts/research-pilot.ts aggregate --study 1 --out outputs/local-backup/pilot/aggregate-001.json
```

Замените 1 фактическими ID, которые вернул сервер. Отдельный `basis-001.txt` содержит основание предварительной оценки минимум 10 символов, без ФИО/контактов. В слепых JSON после скачивания стоят пустые оценки: до импорта их должны заполнить реальные разрешённые оценщики. CLI отвергает незаполненный пакет, сторонний URL и запись приватного отчёта вне папки `local-backup`; API дополнительно проверяет владение, согласие, полную когорту и уникальность авторов.

## Итог и удаление

Используйте существующие показатели: полные пары, матрица `confirmed/not_confirmed`, балл B−A, частичный зачёт по шаблонам/исходным группам, пропуски/неоднозначности, два раздельных источника времени, совпадение с каждой независимой оценкой **о пороге заданного грейда**, точное совпадение двух исходных экспертных категорий и их расхождения. Добавьте знаменатели и Wilson-интервал, не трактуйте несданный Middle как доказанный Junior. Происхождение исходной разметки и реальные авторы подтверждаются отдельным протоколом, не кнопкой.

Отзывы/срок удаляют ответы и строки оценщиков из приложения; оператор удаляет скачанные копии, исходную работу и связь кодов с людьми. Публичный aggregate просмотрите на риск узнавания малых групп. Ни исходные ответы, ни cookie, ни коды людей не включать в конкурсный ZIP. Исследование не меняет рабочий профиль, обычные попытки и cooldown; существующие серверные проверки прав/отзыва/retention остаются включены.
