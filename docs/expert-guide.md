# Signal — инструкция эксперту

Сервис помогает кандидату показать навыки и выбрать предложение, а работодателю — найти специалиста под конкретные требования. Ниже приведён локальный запуск и короткий сквозной сценарий проверки.

## 1. Подготовка

Установите и запустите Docker Desktop с Linux containers. На Linux подойдут Docker Engine и плагин Compose. Для скачивания образов и зависимостей нужен интернет. Освободите порты `4450` (сервис), `55450` (PostgreSQL) и `8050` (локальная почта).

Скачайте [исходники ZIP с Google Drive](https://drive.google.com/file/d/1SgEiJjwBc_sOsU3xDT83kRO0z_8_tMRb/view?usp=drivesdk) и распакуйте архив. Альтернатива — [GitHub](https://github.com/MasterKSAF/fsp-signal-best-match/tree/codex/signal-delivery-20261009), но репозиторий пока приватный; без доступа используйте ZIP. В Windows выберите короткий путь, например `C:\Signal`.

Все следующие команды выполняются в корне скачанной папки, рядом с `compose.yaml`. Отдельные Node.js, pnpm и PostgreSQL на компьютере не нужны.

## 2. Сборка и запуск

В **Windows, PowerShell 7** выполните:

```powershell
$signalNodeImage = 'node:24-bookworm-slim@sha256:' +
  '0e0ff40c39bc087845bfb27465a0df4ea419520094bc35842ff83dd8cbe6f9b6'
docker run --rm -v "${PWD}:/app" -w /app $signalNodeImage `
  node scripts/setup-env.mjs
docker compose -p signal-release-n-final --profile full `
  up -d --build --wait --wait-timeout 180
```

В **Linux, Bash** выполните:

```bash
signalNodeImage='node:24-bookworm-slim@sha256:'
signalNodeImage+='0e0ff40c39bc087845bfb27465a0df4ea419520094bc35842ff83dd8cbe6f9b6'
docker run --rm --user "$(id -u):$(id -g)" \
  -v "${PWD}:/app" -w /app "$signalNodeImage" \
  node scripts/setup-env.mjs
docker compose -p signal-release-n-final --profile full \
  up -d --build --wait --wait-timeout 180
```

Параметр `--user` в Linux создаёт `.env` от имени текущего пользователя, чтобы следующая команда Compose могла её прочитать.

Первая команда создаёт `.env` из примера и генерирует секрет подтверждения регистрации. Если `.env` уже существует, команда её не перезаписывает. Не передавайте этот файл вместе с исходниками.

При запуске автоматически выполняются миграции **0000–0019** и подготовка демонстрационных данных. Первый запуск дольше последующих: Docker скачивает образы, устанавливает зависимости по зафиксированным версиям и собирает приложение.

Проверьте состояние:

```sh
docker compose -p signal-release-n-final --profile full ps
```

Откройте [сервис](http://localhost:4450). У [проверки API](http://localhost:4450/api/healthz) должен быть успешный ответ. [OpenAPI](http://localhost:4450/api/openapi.yaml) доступен на том же стенде.

## 3. Вход

**Быстрый обзор.** На главной нажмите «Войти», включите Demo и выберите «Я кандидат» либо «Я работодатель». Используйте обе роли в Demo, чтобы работать с одним демонстрационным набором. Данные и исходные результаты в этом режиме вымышленные.

**Проверка регистрации.** Создайте обычный аккаунт кандидата или работодателя. Откройте [Mailpit](http://localhost:8050), найдите письмо на указанный адрес и введите код в открытой форме подтверждения. В локальном стенде внешняя почта не используется. Для собственного сценария создайте два обычных аккаунта; они отделены от Demo.

Для одновременной проверки удобно открыть кандидата и работодателя в двух разных браузерах или в обычном и приватном окне: у них будут отдельные сессии.

## 4. Сквозной сценарий двух ролей

Для этого маршрута зарегистрируйте два обычных аккаунта из предыдущего раздела. В Demo можно отдельно посмотреть уже подготовленные вакансии и профили.

1. **Работодатель:** заполните данные компании, создайте и опубликуйте вакансию «Backend-разработчик»: Junior, Python, удалённо, 100–150 тыс. ₽ в месяц до вычета налогов. Для общего грейда и Python выберите **«Достаточно заявленного»**.
2. **Кандидат:** создайте резюме Backend-разработчика с теми же уровнем, Python и условиями. Активируйте резюме, разрешите каталог, подбор и предложения. Откройте предпросмотр и скачайте PDF или Word.
3. **Кандидат:** найдите опубликованную вакансию, откликнитесь этим резюме и проверьте запись в «Моих откликах».
4. **Работодатель:** в «Откликах» найдите тот же отклик и измените статус. **Кандидат:** проверьте изменение у себя.
5. **Работодатель:** создайте приватный запрос с теми же условиями и режимом **«Достаточно заявленного»** для грейда и Python. В «Подборе специалистов» выберите этот запрос, найдите резюме кандидата и сохраните в отбор. Проверьте список и счётчик запроса.
6. **Работодатель:** отправьте этому кандидату приглашение с условиями. **Кандидат:** примите его с согласием на контакты. Проверьте доступ к контактам у работодателя, затем отзовите согласие и убедитесь, что доступ закрыт.

Отдельно откройте паспорт навыков: переключите конкретное резюме, все резюме и режим без резюме. Пройдите проверку навыка и посмотрите результат. Подтверждение общего грейда требует всей обязательной матрицы специализации; один тест его не гарантирует. Затем можно сравнить подбор с режимом **«Требуется подтверждение»** и минимальным уровнем навыка: неподтверждённое резюме может перестать подходить.

Дополнительно: работодатель создаёт задание по собственной вакансии, кандидат отправляет ответ, работодатель оценивает его.

## 5. Остановка и сохранение данных

```sh
docker compose -p signal-release-n-final --profile full stop
docker compose -p signal-release-n-final --profile full up -d --wait
```

Данные сохраняются в Docker-томе. Используйте прежнюю `.env` и имя проекта. Команда `down --volumes` удаляет данные и не нужна для обычной остановки.

## Если запуск не получился

- **Docker недоступен:** запустите Docker Desktop и убедитесь, что выбран режим Linux containers.
- **Порт занят:** измените `SIGNAL_HTTP_PORT`, `SIGNAL_DB_PORT` или `SIGNAL_MAIL_PORT` в `.env`, повторите команду запуска и откройте новый адрес сервиса или почты.
- **Первая сборка прервалась:** проверьте интернет и повторите команду. Причину ошибки приложения покажет `docker compose -p signal-release-n-final --profile full logs --tail 80 app`.
