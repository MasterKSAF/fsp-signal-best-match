# Проверка навыков: управляемые программы Signal

Версии на 6 октября 2026: Backend / Python — `signal-backend-python-v6`; Frontend / TypeScript — `signal-frontend-typescript-v2`. Прежние снимки v5/v1 и `kalibr-backend-python-v4` продолжают читаться и оцениваться по своей сохранённой рубрике. В интерфейсе обе программы называются «Проверка навыков». Новая Senior-рубрика требует архитектуру; пороги 67/83 сохранены. Основание и фактические результаты: [локальная валидация](assessment-validation.md).

## Карта компетенций и сценариев

В каждой программе шесть компетенций, три уровня, **по два собственных содержательных шаблона на компетенцию и уровень**: всего 72 записи реестра. Параметры и перестановка вариантов создают формы, но не считаются дополнительными смысловыми шаблонами. В первом Backend-шаблоне диагностики и архитектуры сохранены варианты по трём описаниям роли. В Frontend две прикладные позиции предпочитают разные сценарии для продуктовой, платформенной и доступной роли; при повторе приоритет получает ещё не встречавшийся сценарий.

| Backend-компетенция | Сценарий A | Независимый сценарий B | Критичный |
| --- | --- | --- | --- |
| API-контракты | Сохранённый ответ и replay | Optimistic write и If-Match | Да |
| SQL и данные | Tenant, EXISTS, последняя версия | Отсутствующая связь, NOT EXISTS, детерминированное окно | Да |
| Диагностика | План БД, блокировки, пул | 429, каскад повторов, насыщение очереди | Нет |
| Идемпотентность | Ledger обработанного события | Водяной знак, устаревшие события, разрыв последовательности | Да |
| Архитектура | Outbox, consumer, saga | Expand-contract и наблюдаемый переход данных | Senior: да; Junior/Middle: нет |
| Изменение условий | Рестарт или поздний replay | Инвалидация кеша и ревизия | Нет |

| Frontend-компетенция | Сценарий A | Независимый сценарий B | Критичный |
| --- | --- | --- | --- |
| TypeScript | Discriminated union | Runtime-граница unknown | Да |
| Состояние | Неизменяемый reducer | Производный фильтр и сумма списка | Да |
| Производительность | Main thread, worker, стоимость передачи | Waterfall и граница кеша аккаунта | Нет |
| Доступность | Tab, disabled, возврат фокуса | Ошибка формы, live region, устаревшее сообщение | Да |
| Архитектура | Владение состоянием, URL, ревизия | DTO, адаптер модели, версии кеша | Senior: да; Junior/Middle: нет |
| Асинхронность | Гонка запросов, unmount | Оптимистичная запись и адресный откат | Нет |

| Уровень | Backend: рабочие действия | Frontend: рабочие действия |
| --- | --- | --- |
| Junior | Повтор команды, один ресурс и tenant, простой JOIN, измеримая гипотеза | Ветвление union, runtime-проверка формы объекта, последовательные actions, клавиатурный цикл |
| Middle | Границы ресурса, кардинальность и NULL, retry budget, конкурентный consumer, миграция схемы | Производные данные, сброс состояния, устаревший ответ, сетевые зависимости, URL и адаптер DTO |
| Senior | Порядок валидации и версии, tie-break оконного запроса, gap события, региональный сбой, cutover | Версия входного DTO, stale action, восстановление удалённого фокуса, unmount, стоимость worker и конфликт ревизий |

Это инженерная проектная карта; рыночное соответствие уровня и психометрическая равная сложность пока не измерены на людях. Senior не означает полное знание языка или всех архитектурных практик.

## Формат, зачёт и категория

Форма содержит четыре вычисляемых ответа и два выбора. Позиции: structured, integer, choice, structured, choice, structured. Structured сравнивается по компонентам на фиксированных местах: число компонентов должно совпадать, каждому компоненту назначен равный вес. Integer и choice получают 0 или 100. Нормализуются Unicode, регистр и пробелы; смысл произвольного текста автоматически не оценивается.

Итог — округлённое среднее шести критериев. Junior требует 67, Middle и Senior — 83; **все критичные критерии должны быть решены на 100: три для Junior/Middle и четыре для Senior**, включая безопасную архитектуру/системное изменение. Частичный или отсутствующий критичный ответ нельзя компенсировать остальными заданиями. У исторических v5/v1 остаются их прежние три обязательных критерия; скрытого пересчёта нет. Одинаковая сырая сумма разных уровней не означает одинаковую квалификацию.

Ориентир времени — 300 секунд на Junior, 360 на основные задания Middle/Senior и 300 на перенос условия. Общий срок попытки — 45 минут. Это ограничения продукта и ориентиры, не измеренное время человека. Сохраняются срок, черновик, идемпотентная сдача, повтор через 7 дней и ограничение повышения через 90 дней. Нижняя или неуспешная попытка не обновляет дату, навыки или категорию прежнего более высокого результата.

Перед обычной проверкой требуется завершённый опрос той же специализации. Опрос имеет собственную версию и отдельные шесть вопросов для каждого направления; он рекомендует стартовый уровень, но ничего не подтверждает. Смена направления сохраняет историю опросов и попыток; профиль не получает навыки нового направления автоматически.

## Что именно подтверждается

Backend: Python в пределах показанных трасс, SQL, API contracts, Idempotency, Incident diagnosis, Architecture, Replay safety. Frontend: TypeScript в пределах проверки, Frontend state, Accessibility, Frontend performance, Frontend architecture, Async UI. Дополнительный навык добавляется только при полном прохождении соответствующего критерия в успешной форме.

Общий SQL **не подтверждает PostgreSQL**, общий Python — FastAPI, TypeScript — React/JavaScript/HTML/CSS. У старых v4 записей сохраняются исходные данные; новые шаблоны не дописываются в их историю. Для legacy-подтверждения без templateId показывается это ограничение, а не выдумывается происхождение.

В серверном oracle сохранены версия программы, стабильный ID шаблона, версия шаблона, компетенция, рубрика, ключ и конкретные условия. Разрешённое свидетельство содержит кандидата, попытку, версию программы/шаблона, критерий, балл и дату; различает Signal и Demo. Employer API использует отдельную безопасную проекцию с проверкой согласия. Клиент не получает seed, ключ, blueprint или приватные ответы других людей.

## Управление банком

Дескриптор шаблона имеет ID вида `frontend-typescript.middle.typescript.runtime-boundary`, version=1, программу, грейд, компетенцию, смысловой сценарий и статус. У Senior архитектуры новая version=2 фиксирует изменение обязательности. Новая версия задания/рубрики получает новую версию программы/шаблона; существующий снимок никогда не перезаписывается.

Выдачи считаются по сохранённым `blueprint.templateId` всех попыток кандидата, включая истёкшие. Сначала выдаётся реже встречавшийся шаблон, при равенстве — воспроизводимый выбор; в прикладных Frontend-позициях учитывается роль. Это балансировщик экспозиции, а не адаптивная оценка сложности. Если обе альтернативы недоступны, API возвращает 503 и объясняет компетенцию; неполная форма не создаётся.

Доступность хранится в `signal_bank_template_overrides`; `signal_bank_audit` сохраняет причину, оператора и время. Создание попытки и отключение сериализованы общим advisory lock. Публичный `/api/assessments/programs/{id}/competencies` выдаёт только дескрипторы и правила. Число выдач доступно локальному оператору, без персональных идентификаторов.

Команды из корня проекта, локально с настроенным окружением БД:

```powershell
node --env-file-if-exists=.env --import tsx scripts/manage-assessment-bank.ts inventory
node --env-file-if-exists=.env --import tsx scripts/manage-assessment-bank.ts disable --template frontend-typescript.middle.typescript.runtime-boundary --operator reviewer --reason "Подтверждена неоднозначность формулировки, issue BANK-12"
node --env-file-if-exists=.env --import tsx scripts/manage-assessment-bank.ts enable --template frontend-typescript.middle.typescript.runtime-boundary --operator reviewer --reason "Независимая проверка закрыла issue BANK-12 без изменения условия"
```

Это привилегированный локальный инструмент оператора с доступом к БД. У кандидата и работодателя нет HTTP-прав управления банком. Отключение относится только к **новым** попыткам; активные продолжаются по выданному снимку. Если ошибка действительно делает конкретную попытку некорректной, требуется отдельное явное действие:

```powershell
node --env-file-if-exists=.env --import tsx scripts/manage-assessment-bank.ts annul --attempt 123 --operator reviewer --reason "Ошибка BANK-12 влияет на решение; предоставлена повторная проверка"
```

Пример ID не является поручением аннулировать рабочую попытку. Команда добавляет неизменяемую запись в `signal_assessment_corrections`; условия, ключи, ответы и исходная оценка остаются в истории. Активная попытка прекращается, завершённое доказательство аннулируется. Кандидат видит причину, а новая попытка освобождается только от ограничений этой аннулированной попытки. Если профиль ссылался на неё, транзакционно восстанавливается наивысшее доступное неаннулированное доказательство той же программы; если такого нет, подтверждение снимается с явным основанием. Старые значения не переоцениваются новой формулой. Повторное аннулирование отвергается.

Если восстановлено подтверждение нижнего уровня, 90-дневное ограничение повышения не блокирует замену испорченной попытки: исключение действует только на её программу и грейд до первого последующего неаннулированного завершённого решения. Другие уровни, ограничения обычного повтора и единственная активная попытка остаются защищены. Исключение нельзя запросить через кандидатский API: требуется отдельное действие оператора с причиной и историей.

Исправление ошибки оценщика: отключить шаблон → зафиксировать issue и диапазон влияния → проверить независимые эталоны → выпустить новую версию → отдельно обоснованно аннулировать затронутые попытки → предложить новое прохождение. Массового скрытого пересчёта, повышения или сброса нет. При отзыве доступности или исправлении не нужно редактировать ответы в БД.

## Технические доказательства и ограничения

`tests/assessment-managed.test.ts` проверяет 72 ID, 600 форм, полноту плана, происхождение, экспозицию, выключение и нехватку шаблонов, сохранность v4, критические провалы, перенос ответов, выбор по позиции/длине и опрос Frontend. Отдельный механизм исполняет **показанный** TypeScript через компилятор и JS VM на 120 новых формах: ожидание не вычисляется формулой oracle.

`tests/assessment-managed-golden.test.ts` содержит 54 собственных синтетических эталона новых шаблонов с отдельно разобранными ответами, дополнительный набор Backend с другими исходными числами и фиксированные граничные решения категории. Для 18 исходных Backend-шаблонов сохранены прежние golden-тесты и тесты контекстов. Это рубрики команды, подготовленные с помощью ИИ; внешними экспертными метками они не являются.

Тесты показывают, что простое копирование строки/ID ответа и угадывание позиции/длины не подтверждают форму. Они не доказывают отсутствие возможности внешней помощи, ИИ, обсуждения метода или передачи личности. Разобранный метод может законно помочь решить новую задачу; это не автоматический признак нарушения.

Человеческая сложность, test–retest, время, согласие с внешним экспертом и эффект ознакомления с разобранной формой — **не измерены**, пока нет участников. Локальный [контроль 6 октября](assessment-validation.md) измерил 468 синтетических работ, 234 пары и 36 модельных переносов: 12 содержательных Senior-расхождений до исправления, 0 после; эти показатели не подменяют человеческие наблюдения. Изолированный исследовательский контур использует тот же генератор с серверным `forcedVariant` A/B и не меняет рабочие категории. `forcedVariant` не принимается endpoint-ом рабочего старта.

Контракт дополнений: `docs/contracts/managed-assessment-openapi.json`. Полный контракт и сгенерированный клиент обновляет интеграционная сборка. Финальная браузерная/HTTP-проверка и ID Docker-образа указываются в общем отчёте; модульный тест не заменяет проверку маршрута через интерфейс.

Локальный HTTP-контроль: `node --env-file-if-exists=.env --import tsx scripts/integration-assessment-managed.ts` (по умолчанию API 4312). Он создаёт временные синтетические аккаунты, входит обычным endpoint, проходит опрос и Frontend Junior/Middle/Senior, проверяет ключи происхождения, приватность попыток, PDF, идемпотентность, повторы, отсутствие освежения более высокого доказательства, политику отключения, явную коррекцию и совместимость активной v4. После выполнения удаляет только созданные аккаунты и восстанавливает собственные временные overrides. Отчёт `outputs/verification/assessment-managed-http.json` не содержит ключей и ответов рабочих попыток. Проверка управления банком временно меняет доступность двух Frontend Senior шаблонов, поэтому её запускают в изолированном локальном стенде без параллельной выдачи таких форм.
