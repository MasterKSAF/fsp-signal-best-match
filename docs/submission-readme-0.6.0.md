# Signal 0.6.0 · комплект Best Match

Комплект предназначен для самостоятельной локальной проверки решения спецтрека Федерации спортивного программирования. Материалы 0.5 сохранены отдельно. Архив сам по себе не выполняет публикацию, внешний хостинг или отправку конкурсной заявки.

## Сначала проверить

1. Сверить SHA256 файлов с `submission-manifest.json` и прочитать `verification/final-report.json`. Он указывает фактический принятый срез, результаты и ограничения. Успех отдельных сред не переносится автоматически на другие проверки.
2. Распаковать `fsp-signal-source-0.6.0.zip`. Внутри `fsp-signal/README.md`, `RELEASE-METADATA.json` и `SOURCE-MANIFEST.json`. Сборка использует lockfile и Docker Compose; исходный ZIP после проверки остаётся неизменным. Более поздние протоколы чистого запуска и медиа передаются внешними companion-файлами.
3. Для собственного экзамена использовать `docs/reviewer-access.md`: каждому проверяющему отдельные кандидат и компания. Общий Demo показывает подготовленные синтетические примеры. Локальный инструмент выдаёт случайные пароли вне исходников; учётные данные не входят в публичный комплект. Контакты команды в презентации разрешены пользователем.
4. Для воспроизведения проверки ZIP создать в собственной распакованной копии `outputs/release-0.6.0` и скопировать туда **тот же** исходный ZIP. Нужны Python 3, PowerShell 7, Node.js 24, pnpm 11.25.0 и Docker Desktop. Из корня этой копии выполнить `python scripts/audit-source-privacy-v060.py --expected-sha256 <SHA256 ZIP из submission-manifest.json>`, затем в PowerShell 7 `scripts/clean-source-launch-v060.ps1 -ExpectedSha256 <тот же SHA256> -FreezeReleased`. Guard проверяет собственный свежий privacy proof и ZIP; прежний протокол комплекта не подставляется вместо нового запуска. Проверочный Docker-стенд использует отдельные 4334/55441/8034 и прекращает работу при конфликте портов.

## Что смотреть

- `Signal-Pitch.pptx` — редактируемая презентация по конкурсному шаблону; `Signal-Pitch.pdf` — визуальная копия сохранённого PPTX.
- `Signal-Technical-Description.pdf` — архитектура, квалификация, подбор, ограничения, интеграция ФСП, API, библиотеки и запуск.
- `Signal-Demo.mp4` — подписанный монтаж настоящих экранов с синтетическими аккаунтами. Это не непрерывная запись сессии или исследование людей. `Signal-Demo-audit.json` связывает оригинальные JPEG/PNG, подписи и SHA; масштабирование и H264-кодирование видео не объявляются побитовым сохранением пикселей.
- `verification/` — отдельно функциональный HTTP, браузер, полная нагрузка, privacy, чистый запуск и визуальный просмотр медиа. Итоговый отчёт содержит точные версии и ссылки на фактические протоколы.

## Основные сценарии

Кандидат создаёт до пяти резюме, выбирает IT-направление, заполняет профессиональные поля и первичный опрос, явно подтверждает заявленный уровень и проходит квалификационный экзамен Signal. Общий реестр «Мои подтверждения» хранит критерий, дату, версию и применимость каждому документу. Копирование не создаёт новый источник и не снимает cooldown. Полный грейд другой программы не переносится; индивидуальный критерий отличается от грейда полной программы. Ревизии защищают черновик при работе в двух вкладках.

Компания задаёт потребность и получает объяснение по одному целому подходящему резюме человека. Каталог допускает опубликованный документ без грейда, но строгий подбор требует текущей квалификации. Требования разных документов не склеиваются. Категории упорядочены нейтрально; спортивные результаты влияют внутри категории. Приглашение и добровольный отклик открывают контактные поля только выбранной компании после согласия.

Практика компании сохраняет выбранные резюме, ревизию и безопасный контекст. Смена основного не переносит задание. Скрытие, удаление, смена направления, отзыв разрешения или квалификации прекращают новые действия; исторический результат сохраняется. Оценка компании не присваивает общий грейд Signal. Старые задания без снимка отмечены `legacy_unbound`.

Жалобы, блокировки, ограничения и апелляции имеют серверные права и аудит. Жалоба не является автоматической санкцией; автор и закрытый текст работодателю не передаются. Апелляцию решает другой модератор. Самостоятельный reviewer не получает права модератора или готовую успешную квалификацию.

## Границы результата

Демонстрация, нагрузки и исследовательские работы синтетические; независимых человеческих участников — 0. Настоящий реестр ФСП не подключён. Бонус участия/призового места/победы — политика проекта, а не правило Федерации о спортивном разряде. Новая политика категорий имеет измеренное снижение nDCG на фиксированном синтетическом наборе; исходные labels не подгонялись.

Native Windows WorkingSet в нагрузочном протоколе не называется Docker cgroup memory. Чистый Docker-запуск — отдельная проверка доставки, не повтор полной нагрузки. Локальные пороги не являются SLA организатора. Privacy-аудит ограничен перечисленными файлами, известными значениями и текстом/XML/PDF; без OCR, анализа речи/видео и универсальной гарантии отсутствия любых персональных данных.
