# ФСП: фактический контракт на 8 октября 2026

Настоящий реестр ФСП и проверка принадлежности ID не подключены. В официальном ТЗ и ответах организатора нет предоставленного API или протокола авторизации. Сохранение идентификатора не подтверждает спортивные результаты, навыки или грейд. [Историческое описание прежнего Demo-импорта](history/fsp-integration-before-a01-a11-20261008.md) сохранено отдельно.

## Операции кандидата

Все операции требуют собственной подтверждённой сессии кандидата. Ответы персональные: `Cache-Control: no-store, private`; изменение дополнительно проверяет доверенный Origin.

| Операция | Тело / результат |
|---|---|
| `GET /api/me/fsp-connection` | Текущее собственное состояние. Пустая история — нормальное состояние. |
| `PUT /api/me/fsp-connection` | Только `{"fspId":"MY-ID-22"}`. Пробелы по краям удаляются; затем 1–100 ASCII символов, первый буква/цифра, остальные буквы/цифры/`._:-`. Это локальное ограничение ввода, а не официальный формат ФСП. Дополнительные поля, включая `consentImport`, дают 400. |
| `POST /api/me/fsp-connection/import` | Только `{"consentImport":true}`. Без согласия/с лишними полями: 400 `fsp_import_consent_required`; без ID: 409 `fsp_id_required`; с ID: 503 `registry_not_configured`. Импорт и запись согласия не происходят. |
| `DELETE /api/me/fsp-connection` | Идемпотентно отключает собственный ID, результаты и внешний источник; очищает флаг ФСП в профиле. Сохраняет минимальные исторические отметки согласия/отзыва, если они были. Проверки Signal и согласия на контакты не меняются. |

Каждый PUT обновляет `requestedAt` и сбрасывает прежние `consentedAt`, `verifiedAt`, `importedAt`, `providerVersion`, достижения и доверие к внешнему источнику. Ответ: `status: pending`, `provenance: user_supplied`, `hasHistory: false`, `importAvailable: false`, `demoAvailable: false`, `demoFixtureId: null`, бонус 0. Даже `FSP-DEMO-2026` сейчас сохраняется только как непроверенный ID. Повторный идентичный PUT не обещает сохранение старой даты запроса.

## Исторические Demo-данные и подбор

В уже сохранённых обзорных Demo-профилях может оставаться явно синтетическая спортивная история. Она читается только для Demo-аккаунта при включённом Demo и строгой проверке исходной записи: точный fixture ID, поддерживаемая версия, согласие, дата проверки, отсутствие отзыва и валидные достижения. Ни одна из перечисленных HTTP-операций не создаёт такую историю. Сбой, введённый ID или старый `hasFspHistory` сами по себе не дают бонус.

Политика команды `fsp-category-results-v1`: наибольший явно подтверждённый исход «участие / призовое место / победа» даёт 1 / 2 / 3 только внутри одинаковой специализации и подтверждённой категории. Результаты не суммируются, не повышают грейд или общий балл соответствия. Неуточнённый исход остаётся без числового бонуса. Это политика продукта на синтетических данных, не официальный спортивный разряд и не оценка точности реального найма.

## Будущее подключение

Нужны официальный провайдер и доверенная проверка связи пользователя с ID, отдельное согласие на импорт, правила источника/срока/отзыва и обработка недоступности. Интерфейс `FspRegistryProvider` — граница будущего адаптера. Его внутренний synthetic fixture не доступен через текущий маршрут импорта. Пока интеграция не настроена, приложение показывает сохранённый ID без ложной проверки.

Контракт: [основной OpenAPI](../lib/api-spec/openapi.yaml), [синхронный фрагмент в JSON-совместимом YAML](contracts/fsp-openapi.yaml). Реализация: `signal-fsp.ts`, `fsp-provider.ts`, `fsp-results.ts`. Проверки: `fsp-identity-save.test.ts`, `fsp-contract-current.test.ts` и текущий HTTP-протокол аудита A10. Наличие схемы или внутреннего provider fixture не означает выполненный импорт.
