## Реализация и воспроизведение

- `artifacts/api-server/src/lib/microtask-recipient-query.ts`, маршрут `signal-microtasks.ts`, компонент `microtasks.tsx`. В UI поиск выполняется по Enter/«Найти получателя», продолжение — «Показать ещё резюме». Смена поиска, грейда, шаблона/версии/направления сбрасывает выбранное резюме; ошибка отправки очищает выбор и обновляет доступный список. Сервер при отправке повторно проверяет текущие права и сохраняет точное `resumeId`/ревизию; недельные ограничения не изменены.
- `scripts/src/seed-overview-demo.ts` вызывается штатным `db:seed`, требует `DEMO_MODE=true`. Для уже подготовленного окружения есть отдельный `scripts/seed-overview-demo.ts`. Добавляются только новые зарезервированные синтетические идентичности общего Demo; существующие ordinary/reviewer записи и результаты не обновляются. Коллизия зарезервированной идентичности без маркера приводит к отказу, а не перезаписи.
- Новые guarded runners: `scripts/microtask-recipient-audit-http.ts`, `scripts/demo-overview-audit-http.ts`, `scripts/independent-fixes-full-http.ts`. Они принимают только свой новый локальный API/имя БД и явный owned-isolated флаг. Baseline recipient runner имеет отдельную узкую ветку для старого compiled 4365 и очищает только свою маркированную фикстуру.
- `independent-fixes-full-http.ts --prepare` регистрирует новые ordinary аккаунты и проверяет требования; `--complete --manifest=<absolute private manifest>` проходит реальные экзамены и оставшиеся сценарии. Manifest хранится вне репозитория. Новый полный прогон требует новых аккаунтов: успешные экзамены и cooldown не сбрасываются.

Targeted unit: 19 PASS (`microtask-recipient-query`, `microtask-resume`, `opportunity-rules`, `reviewer-scope`); из них 3 новые проверки границ/курсорного контекста/Unicode-поиска. Typecheck API, frontend и scripts прошёл после изменений. Полный build/unit и финальную браузерную приёмку выполняет координатор.

## Сохранённые неудачи и ограничения

- `demo-overview-468c207c.json`: первое создание и idempotence прошли, но runner прочитал несуществующий `catalog.items` вместо реального `catalog.candidates`. Код продукта не требовал изменения; исправлен runner, свежий отдельный отчёт PASS сохранён.
- `full-http-9ff2f713-complete-1791381086208.json`: четыре этапа прошли, затем runner прочитал `explanation.candidate.resumeId` вместо верхнеуровневого `explanation.resumeId`. Неудача сохранена. Полный маршрут повторён с начала на новых ordinary аккаунтах `89221097`; готовый грейд в БД не задавался, cooldown старой учётной записи не обходился.
- HTTP-экзамены функционального полного маршрута используют закрытый oracle только собственной свежевыданной тестовой попытки для синтетических ответов. Старт, сохранение, повторный вход, оценивание и подтверждение идут штатными серверными HTTP-маршрутами. Это проверка переноса данных и прав, не независимый экзамен человека, не измерение сложности и не доказательство защиты от внешней помощи. Смысловой контроль банка и независимый matching holdout — отдельные эксперименты.
- Новое наполнение пока проверено на отдельной БД. Применение добавочного Demo к общему UI4314 выполняет координатор после проверки сохранности. Пользовательские/ревьюерские данные нельзя сбрасывать ради красивого примера.
- Презентация, ролик, архив, упаковка, облако, commit и push в эту работу не входят.
