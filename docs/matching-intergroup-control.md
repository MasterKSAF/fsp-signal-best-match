# Межгрупповой контроль QA-01

Набор `signal-intergroup-control-v1` подготовлен отдельным QA-агентом как явные синтетические бизнес-суждения до реализации новой политики подбора и до первого прогона. Это разметка с помощью ИИ; людей, внешних экспертов и реальных наймов здесь нет. Набор не доказывает человеческую сложность разных банков и не даёт официальных конкурсных баллов.

## Потребности и метки

Восемь потребностей включают по 12 допустимых кандидатов: 96 пар. Три сценария заранее отнесены к development, пять — к control-holdout. Отложенный раздел использован первым измерением; менять метки или числовые веса ради его результата нельзя. После последующей независимой QA общая политика полноты происхождения доработана: нынешний повторный прогон — регрессия уже использованного контроля, не нетронутый holdout финальной политики.

- Команда ledger API: реальные подтверждения SQL/API contracts/idempotency и удалённая работа; Senior допускается минимальным Middle.
- Непрозрачные версии и рубрики: полнота соответствия задачи не заменяется строковым порядком ID.
- Доступный интерфейс TypeScript: реальные требования state/accessibility/performance при разных грейдах и версиях.
- Равные прочие условия и одна категория/программа/версия/рубрика: 100 лучше 83, псевдонимы направлены против качества.
- Два измеренных банка и исторические профили без полного протокола: качество неизвестно (`null`), сохранённый `verifiedScore=99` не считается доказательством результата.
- Реальная зарплатная совместимость: известный конфликт, совместимые месячные/годовые gross-ожидания и неизвестное соотношение gross/net различаются.
- Компромисс давности: rubric предпочитает двухдневный 100 сегодняшнему 83 внутри одной группы; сохраняется проигрыш, если политика выдаёт иначе.
- Ограниченный положительный сигнал ФСП у допустимых кандидатов при равном соответствии задачи.

Метки 0–4 записаны явным числом и отдельной причиной для каждой пары; они не вычисляются из score, eligibility или matcher. Порог релевантности для P@5 — 2. DCG использует `2^label−1`, P@5 всегда имеет знаменатель 5. Пустые знаменатели nDCG/recall сохраняют `null`; этот набор сам не содержит пустых/коротких пулов.

## Что проверяют преобразования

В замороженном файле заранее записаны: биективное переименование синтетических технических версий/рубрик с сохранением разбиения на группы; чистое повышение допустимого грейда исторического профиля; 100/83 при обратных псевдонимах; неизвестное качество; три перестановки входов; все тройки кандидатов после назначения позиций.

Переименование означает только эквивалентность непрозрачных идентификаторов в синтетическом тесте. Метаданные не удаляются, позиции внутри групп и результаты сохраняются. Это не утверждение, что две реальные версии банка одинаковы по человеческой сложности. Сравнение сырого качества между разными группами не допускается.

`scripts/evaluate-intergroup-control.ts` импортирует production `evaluateMatch` и `rankMatches`; v4 импортируется из сохранённого снимка. Один eligible pool используется для всех методов. Перед/после, random/reverse, поиск по словам, прежний v3 и удаление качества сохраняются в отчёте. Удаление качества — диагностическая абляция; оно не отзывает попытку и не меняет группу/допуск.

## Границы

Это контроль порядка среди уже допустимых кандидатов. Приватностных отрицательных примеров нет, поэтому соответствующий знаменатель равен 0 и ставка `null`: безопасность и допуск продолжают измеряться прежним замороженным контролем. Здесь нет работающего Docker/API, БД, поведения людей или оценки промышленной полезности. Измерение — локальный вызов общих production-функций.

Техническая стабильность total order не означает правильность бизнес-политики. Любой сохранённый проигрыш по меткам публикуется без перестановки labels.
