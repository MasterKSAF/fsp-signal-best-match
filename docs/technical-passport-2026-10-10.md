# Signal: технический паспорт

**Осознанный выбор - лучшее начало!**

Сервис подбора ИТ-специалистов и подходящих предложений. Команда **Best Match**, специальный трек Федерации спортивного программирования, ЛЦТ 2026. Версия приложения **0.7.0**.

Паспорт объединяет назначение сервиса, полный каталог возможностей, устройство решения, установку, сценарии обеих ролей, программный интерфейс и ссылки на материалы. Он рассчитан на эксперта, который впервые открывает проект и хочет самостоятельно пройти путь от скачивания до проверки результата.

## 1. Назначение и логика решения

Кандидат представляет свой опыт в нескольких резюме, подтверждает отдельные навыки, выбирает работу и управляет раскрытием своих данных. Работодатель публикует вакансии, формулирует приватные запросы, рассматривает отклики, сравнивает специалистов, сохраняет отборы и направляет приглашения с конкретными условиями.

Основная единица подбора - **конкретное резюме человека**. Его направление, заявленный грейд, подтверждённые навыки, условия и разрешения рассматриваются вместе. Это сохраняет связь между профессиональной целью кандидата и потребностью компании.

Подтверждения навыков принадлежат аккаунту и применяются к подходящим резюме. Общий подтверждённый грейд формируется по обязательной матрице специализации. Отклик, приглашение и задание компании сохраняют свои основания, версии и условия.

### Как читать паспорт

- Раздел 2 содержит все ссылки и описание выдаваемых материалов.
- Разделы 3 и 4 проводят через установку и реальные сценарии двух ролей.
- Раздел 5 - полный функциональный каталог.
- Разделы 6-8 описывают архитектуру, данные, безопасность и API.
- Разделы 9 и 10 помогают повторить проверку и ориентироваться в исходниках.

## 3. Установка и эксплуатация через Docker

### 3.1. Требования и подготовка

Подойдёт Windows с [PowerShell 7](https://learn.microsoft.com/en-us/powershell/scripting/install/install-powershell-on-windows) и [Docker Desktop](https://docs.docker.com/desktop/setup/install/windows-install/) в режиме Linux containers либо Linux с [Docker Engine](https://docs.docker.com/engine/install/), плагином Docker Compose и Bash. Ссылки ведут на официальные инструкции установки. Docker должен быть запущен. Для первого скачивания образов и зависимостей нужен интернет. Отдельная установка Node.js, pnpm и PostgreSQL на компьютер для этого маршрута не требуется.

Скачайте [ZIP исходников](https://drive.google.com/file/d/1SgEiJjwBc_sOsU3xDT83kRO0z_8_tMRb/view?usp=drivesdk), распакуйте его и откройте терминал в папке, где лежат `compose.yaml` и `Dockerfile`. Для Windows удобен короткий путь, например `C:\Signal`.

Стандартные локальные порты: **4450** - приложение, **55450** - PostgreSQL, **8050** - просмотр регистрационной почты. Перед запуском они должны быть свободны. Если на компьютере уже есть экземпляр Signal, для нового стенда выберите другое имя проекта и отдельные порты.

### 3.2. Windows: PowerShell 7

Выполните команды по порядку:

```powershell
$signalNodeImage = 'node:24-bookworm-slim@sha256:' +
  '0e0ff40c39bc087845bfb27465a0df4ea419520094bc35842ff83dd8cbe6f9b6'
docker run --rm -v "${PWD}:/app" -w /app $signalNodeImage `
  node scripts/setup-env.mjs
docker compose -p signal-release-n-final --profile full `
  up -d --build --wait --wait-timeout 180
```

### 3.3. Linux: Bash

```bash
signalNodeImage='node:24-bookworm-slim@sha256:'
signalNodeImage+='0e0ff40c39bc087845bfb27465a0df4ea419520094bc35842ff83dd8cbe6f9b6'
docker run --rm --user "$(id -u):$(id -g)" \
  -v "${PWD}:/app" -w /app "$signalNodeImage" \
  node scripts/setup-env.mjs
docker compose -p signal-release-n-final --profile full \
  up -d --build --wait --wait-timeout 180
```

В Linux параметр `--user` создаёт `.env` от имени пользователя, который затем выполняет Compose. Скрипт копирует пример окружения, создаёт случайный секрет подтверждения регистрации и сохраняет существующую `.env`, если она уже есть. Этот локальный файл храните отдельно от распространяемых исходников.

### 3.4. Что происходит при первом старте

Docker устанавливает зависимости по `pnpm-lock.yaml`, проверяет типы и собирает сервер и клиент. Compose поднимает PostgreSQL и Mailpit, затем приложение. Перед запуском API автоматически выполняются **20 миграций, 0000-0019**, и подготовка Demo-данных.

Проверьте сервисы:

```sh
docker compose -p signal-release-n-final --profile full ps
```

| Адрес | Назначение |
|---|---|
| [http://localhost:4450](http://localhost:4450) | Главная страница и кабинеты Signal. |
| [http://localhost:4450/api/healthz](http://localhost:4450/api/healthz) | Проверка готовности API. |
| [http://localhost:4450/api/openapi.yaml](http://localhost:4450/api/openapi.yaml) | Спецификация API запущенного экземпляра. |
| [http://localhost:8050](http://localhost:8050) | Mailpit: письма с кодами обычной регистрации. |

### 3.5. Настройки локального стенда

| Параметр | Назначение |
|---|---|
| `SIGNAL_HTTP_PORT` | Порт приложения на компьютере, стандартно 4450. |
| `SIGNAL_DB_PORT` | Локальный порт PostgreSQL, стандартно 55450. |
| `SIGNAL_MAIL_PORT` | Порт интерфейса Mailpit, стандартно 8050. |
| `POSTGRES_PASSWORD` | Пароль локальной базы; Compose использует его для согласованного подключения приложения. |
| `VERIFICATION_TOKEN_SECRET` | Случайный секрет для подтверждения регистрации, создаваемый `setup-env.mjs`. |

Compose задаёт рабочее соединение с базой через имя сервиса `db`, адрес Mailpit через `mail` и внутренний порт приложения 4310. Флаги `SIGNAL_WORKSPACE_ENABLED` и `SIGNAL_SKILL_MODULES_ENABLED` включают поставляемые рабочие пространства и модульные проверки. Включённый `DEMO_MODE` подготавливает обзорные данные. Публикуемые порты привязаны к `127.0.0.1`.

При смене внешних портов отредактируйте соответствующие три переменные в локальной `.env`, повторите запуск и используйте новые адреса браузера. При смене имени Compose-проекта используйте одно и то же новое имя во всех командах: оно определяет отдельные ресурсы и том данных.

### 3.6. Остановка, повторный запуск и проверка состояния

```sh
docker compose -p signal-release-n-final --profile full stop
docker compose -p signal-release-n-final --profile full up -d --wait
```

Резюме, попытки, отклики, приглашения и настройки сохраняются в томе PostgreSQL. Для продолжения работы используйте прежние `.env` и имя проекта. Для обычной остановки достаточно `stop`; том данных должен сохраняться.

Состояние показывает команда `ps`, журнал приложения открывается так:

```sh
docker compose -p signal-release-n-final --profile full logs --tail 80 app
```

Если скачивание зависимостей было прервано, проверьте интернет и повторите команду сборки и запуска. Если порт занят, задайте свободный в `.env`. Docker Desktop должен работать в режиме Linux containers.

## 4. Последовательные сценарии двух ролей

### 4.1. Начало: Demo или свои аккаунты

Для обзорного знакомства нажмите «Войти», включите Demo и выберите роль кандидата или работодателя. Для взаимодействия с одним демонстрационным набором используйте Demo у обеих сторон. Обзорные профили и исходные результаты обозначены как вымышленные.

Для собственного воспроизводимого сценария зарегистрируйте два обычных аккаунта. На форме регистрации выберите роль, укажите имя или название компании, email и пароль. В Mailpit найдите письмо на этот email и введите код в открытой форме подтверждения. Для одновременной работы откройте роли в разных браузерах либо в обычном и приватном окне.

### 4.2. Подготовить вакансию и резюме

1. **Работодатель:** откройте настройки «О компании» и сохраните сведения организации.
2. В «Моих вакансиях» создайте вакансию «Backend-разработчик»: направление Backend, Junior, обязательный Python, удалённо, 100-150 тыс. рублей в месяц до налогов. Заполните задачи и условия.
3. Для общего грейда и Python выберите **«Достаточно заявленного»**. Опубликуйте вакансию.
4. **Кандидат:** создайте резюме Backend-разработчика, укажите Junior, Python, краткое описание и сопоставимые условия поиска. Сохраните изменения.
5. Активируйте резюме и разрешите подбор, каталог и предложения. Откройте предпросмотр, выберите состав и скачайте PDF или Word.

В результате у работодателя есть опубликованное предложение, у кандидата - конкретное доступное резюме, а требования первого сценария проверяют заявленные параметры.

### 4.3. Пройти отклик и смену статуса

1. **Кандидат:** в «Вакансиях и откликах» найдите созданную вакансию по названию или компании.
2. Откройте описание, проверьте условия и отправьте отклик выбранным резюме с нужными согласиями.
3. Проверьте запись в «Моих откликах».
4. **Работодатель:** откройте «Отклики», выберите эту вакансию и тот же отклик, просмотрите резюме и нажмите «Отобрать отклик». У кандидата результат отображается как «В рассмотрении».
5. **Кандидат:** обновите свой список и проверьте, что состояние изменилось. Для проверки обратного действия можно отозвать собственный отклик.

### 4.4. Найти через приватный запрос и отправить приглашение

1. **Работодатель:** создайте приватный запрос с теми же направлением, Junior, Python и зарплатными условиями. Для грейда и Python оставьте «Достаточно заявленного».
2. В «Подборе специалистов» выберите этот запрос. Найдите подготовленного кандидата и откройте его резюме.
3. Сохраните человека в отбор. Включите «Только отобранные» и проверьте запись и счётчик именно этого запроса.
4. Начните приглашение, проверьте выбранные запрос и CV, напишите сообщение и задайте реальные условия предложения. Отправьте его.
5. **Кандидат:** откройте приглашение, проверьте компанию и условия, примите его с согласием на раскрытие контактов.
6. **Работодатель:** откройте контакты в принятом приглашении.
7. **Кандидат:** отзовите контактное согласие. **Работодатель:** повторно запросите контакты или документ и проверьте актуальное представление доступа.

### 4.5. Проверить паспорт, экзамен и требования к доказательствам

1. **Кандидат:** откройте паспорт навыков и последовательно выберите конкретное резюме, «Все резюме» и «Без резюме». Сопоставьте показанные навыки и подтверждения.
2. В «Проверке навыков» выберите Python Junior, изучите программу и начните попытку. Решите задания и сохраните несколько ответов.
3. Вернитесь к матрице и откройте ту же попытку: сохранённые ответы восстановятся, а исходный срок продолжит действовать.
4. Завершите проверку до срока, подтвердив отправку. Посмотрите результат по компетенциям и, при успешном прохождении, подтверждение Python Junior в паспорте и относящемся к нему резюме.
5. Для общего Backend Junior дополнительно подтвердите SQL и Backend engineering на требуемом уровне. Общий грейд появится при полном покрытии обязательной матрицы.
6. **Работодатель:** измените требования своего запроса на «Требуется подтверждение», отдельно задайте минимальный уровень навыка и повторите подбор. Сравните основания допуска и объяснение для того же CV.

### 4.6. Предложить и оценить практическое задание

1. **Работодатель:** откройте «Задания кандидатам», создайте задание по своей вакансии, задайте компетенцию, ситуацию, срок и рубрику оценки.
2. Выберите доступное резюме адресата и направьте задание.
3. **Кандидат:** в «Практике» откройте предложение, примите его и отправьте подготовленный ответ.
4. **Работодатель:** найдите ответ, выставьте баллы по критериям, поясните оценку и сохраните обратную связь.
5. **Кандидат:** посмотрите результат и настройте разрешения на его использование.

Для дополнительного обзора создайте второе CV с другим профессиональным акцентом, сравните его паспорт и экспорт, затем изучите темы, настройки, помощь и обращения.

## 5. Полный каталог функций

### 5.1. Два кабинета и единое рабочее пространство

#### Кабинет кандидата

Кандидату доступны обзор состояния профиля, «Мои резюме», паспорт и проверка навыков, приглашения, вакансии и отклики, практика, обращения и управление доступом. Обзор помогает перейти от заполнения резюме к подтверждению навыков и поиску предложений. Выбранное резюме задаёт контекст дальнейших действий.

#### Кабинет работодателя

Компания работает с вакансиями и приватными запросами, подбором специалистов, откликами, заданиями кандидатам и приглашениями. Счётчики откликов и отобранных ведут к соответствующим спискам. Данные компании доступны в настройках; обращения и ограничения собраны в отдельном разделе.

#### Вход, оформление и навигация

- Регистрация кандидата или работодателя с подтверждением email, вход и выход из аккаунта. В настройках видны роль, адрес, статус подтверждения и дата регистрации; можно изменить имя, а кандидату - профессиональный псевдоним.
- Demo позволяет познакомиться с обеими ролями на обозначенных вымышленных данных. Для собственного сквозного сценария используются два обычных аккаунта.
- Четыре цветовые темы: «Жемчуг», «Кашемир», «Графит» и «Полночь»; режим «Как в системе» следует оформлению устройства. Настраиваются режим и скорость анимаций.
- Боковое меню, мобильное меню и кнопки «Назад» / «Вперёд» помогают переходить между разделами. История переходов работает внутри сервиса и учитывает текущий аккаунт.
- Контекстные пояснения раскрывают смысл поля или действия. Справочный помощник отвечает на вопросы о разделах и предлагает ссылки на нужные действия. Личный план подготовки содержит темы по специализации и отметки о повторении, сохраняемые на устройстве.

### 5.2. До пяти резюме для разных профессиональных задач

Один кандидат может вести **до пяти резюме**. Это позволяет отдельно представить, например, опыт Backend-разработчика и интерес к Python API, сохранив общий аккаунт и накопленные подтверждения.

#### Создание и содержание

Можно создать резюме, скопировать своё существующее, отредактировать его, свернуть редактор, активировать или скрыть карточку и удалить выбранное резюме. Копия служит основой для другого профессионального акцента; параметры размещения настраиваются для неё отдельно.

В редакторе задаются название, направление, заявленный грейд, навыки и краткий рассказ о себе. Развёрнутая часть включает опыт работы, проекты, образование, портфолио, ссылки и личные навыки. Условия поиска содержат зарплатные ожидания, период и способ указания зарплаты, формат работы и локацию. Справочники помогают последовательно указывать навыки, роли и условия.

Профессиональный опрос из шести вопросов рекомендует стартовый уровень. Кандидат использует эту рекомендацию при выборе проверки; подтверждённый уровень определяется результатами проверок.

#### Управление и обратная связь

- Карточка показывает описание, навыки с их статусами, заявленный и подтверждённый грейд, дату обновления и текущую видимость.
- Отдельные показатели показывают заполнение резюме и долю подтверждённых навыков. В редакторе можно раскрыть состав заполнения и перейти к следующей проверке.
- Счётчики просмотров и скачиваний показывают активность за указанный в карточке период.
- Кнопка «Сохранить изменения» сохраняет изменённые разделы открытого резюме. При одновременном редактировании система учитывает версии и предлагает сравнить изменения.
- Переключатель резюме сохраняет понятный рабочий контекст для паспорта, отклика, практики и документов.

Подтверждения принадлежат аккаунту. Удаление одного резюме сохраняет историю проверок и возможность применить подходящие подтверждения в других резюме.

### 5.3. Паспорт навыков: заявления, подтверждения и общий грейд

Паспорт объединяет навыки и основания их подтверждения. В нём раздельно показаны **подтверждённые**, **заявленные** и **рекомендованные** навыки. Для подтверждения можно посмотреть уровень, источник и историю проверки; для следующего шага - открыть соответствующий модуль.

#### Три режима просмотра

| Режим | Что получает кандидат |
|---|---|
| Конкретное резюме | Навыки его стека и направления, применимые подтверждения и рекомендации для этой профессиональной цели. |
| Все резюме | Общую картину навыков из резюме без дублей и их связь с профессиональными направлениями. |
| Без резюме | Подтверждения и историю аккаунта как самостоятельный набор достижений. |

#### Как связаны уровни

Заявленный грейд отражает профессиональную цель кандидата. Подтверждённый уровень отдельного навыка опирается на конкретную проверку. Общий подтверждённый грейд резюме складывается из покрытия обязательной матрицы выбранной специализации.

| Направление | Обязательные составляющие общего грейда |
|---|---|
| Backend | Заявленный поддерживаемый язык Python или TypeScript, SQL и Backend engineering. |
| Frontend | TypeScript, заявленный React и Frontend engineering. |

Каждая обязательная составляющая должна иметь действующее подтверждение нужного уровня. Система выбирает наивысший полностью покрытый грейд в пределах заявленной цели и показывает основание. Балл попытки, уровень навыка, общий грейд и соответствие вакансии представлены как отдельные показатели.

Подтверждение применяется к релевантным резюме аккаунта с учётом их стека. В истории сохраняются дата, версия программы, результат и исходные критерии. Изменения состава резюме приводят к актуальному пересчёту применимости доказательств.

### 5.4. Проверка навыков: шесть модулей и три уровня

В банке `signal-skills-2026-10-v6` доступны **Python, SQL, TypeScript, React, Backend engineering и Frontend engineering**. Для каждого модуля предусмотрены **Junior, Middle и Senior** - всего 18 сочетаний навыка и уровня.

| Модуль | Что проверяется |
|---|---|
| Python | Коллекции и ссылки, итерация, функции и область видимости, исключения, ресурсы, внешние данные. |
| SQL | Соединения и кардинальность, агрегаты, NULL, транзакции, оконные функции, целостность данных. |
| TypeScript | Сужение типов, поведение во время выполнения, generics, преобразование структур, асинхронность, неизменяемость. |
| React | Очередь обновлений состояния, замыкания, эффекты и очистка, идентичность компонентов, формы, композиция. |
| Backend engineering | Контракты API, согласованность данных, повторы и сбои, диагностика, безопасность, связанные инженерные решения. |
| Frontend engineering | Модель состояния, доступность, производительность, асинхронный интерфейс, архитектура, связанные решения. |

#### Подготовка и прохождение

Кандидат выбирает навык и уровень в матрице, изучает программу, критерии и условия, затем явно начинает попытку. Каждая форма содержит шесть заданий по разным компетенциям. Junior и Middle рассчитаны на 30 минут, Senior - на 45 минут. Middle добавляет требования к более сложному результату, Senior включает самостоятельные инженерные сценарии и выбор достаточного решения.

Ответы можно сохранять на сервере и продолжать позднее в той же действующей попытке. Интерфейс показывает число заполненных заданий, состояние сохранения и оставшееся время. Локальный черновик помогает восстановить ввод; при конфликте серверной версии пользователь сравнивает варианты и выбирает, какие ответы сохранить.

**Срок фиксируется сервером при старте.** Можно вернуться к матрице, свернуть окно или закрыть вкладку и затем открыть ту же попытку. Её срок окончания остаётся прежним, отсчёт продолжается. По достижении срока приём ответов закрывается, а попытка получает состояние истечения времени. Для получения оценки кандидат отправляет ответы кнопкой завершения до этого срока; перед отправкой видит подтверждение и число заполненных заданий.

#### Результат и история

Сервер оценивает ответы по сохранённой программе и критериям. Для подтверждения требуются как минимум пять верных компетенций из шести и выполнение всех критических требований модуля. Итог раскрывает покрытие компетенций и результат проверки.

Выданная форма сохраняет собственную версию заданий и правил оценки. Банк использует семейства сценариев и варианты, учитывает прежние показы и распределяет новые формы. Действующая попытка восстанавливается с теми же заданиями. Повтор того же навыка и уровня доступен через 24 часа после отправки; действуют суточные лимиты выдачи: до двух форм одного навыка и до восьми форм аккаунта. Интерфейс показывает условия следующего старта.

### 5.5. Вакансии и отклики со стороны кандидата

Кандидат ищет предложения по компании или должности и открывает полное описание вакансии с требованиями и условиями. Каталог опубликованных вакансий доступен также на публичной странице сервиса.

#### Поиск и работа с выдачей

- Фильтры по специализации, общему грейду, навыкам и их минимальному уровню, зарплатной вилке и периоду, формату работы и локации.
- Быстрые фильтры «С заданием», «Без отклика» и «Не заблокированы» помогают выделить подходящие следующие действия.
- Сортировка по новизне и размеру зарплаты, переходы по страницам, видимые применённые фильтры и их сброс.
- Выгрузка всей отфильтрованной выдачи вакансий в XLSX или CSV в пределах указанного интерфейсом лимита.

#### Отклик конкретным резюме

Кандидат выбирает своё резюме и отправляет отклик с относящимися к нему разрешениями. Запись появляется в «Моих откликах» и у работодателя. По ней можно проверить вакансию, использованное резюме, дату и текущее состояние, а также отозвать отклик.

Состояния отклика: **«Отправлен», «Просмотрен», «В рассмотрении», «Отказ» и «Отозван»**. Работодатель меняет состояние в своём кабинете, кандидат видит обновление у себя. Поиск и фильтр по статусу помогают проследить ход рассмотрения.

### 5.6. Вакансии, приватные запросы и точные требования

У компании есть два способа описать потребность. **Вакансия** публикуется для откликов кандидатов. **Приватный запрос** служит внутренней задачей поиска: работодатель задаёт требования и самостоятельно подбирает специалистов.

#### Управление потребностями

Можно создавать, редактировать, искать и сортировать свои вакансии и запросы. Для вакансии предусмотрены черновик, публикация, закрытие и архив; запрос можно архивировать. Удаление сохраняет связанную историю взаимодействий. Каждая карточка ведёт к своему подбору и отобранным; у вакансии есть отдельный список откликов.

В форме указываются роль, направление, грейд, обязательные навыки, формат работы, зарплатная вилка, период выплаты и расчёт до налогов либо на руки. Вакансия дополнительно содержит локацию и публичные задачи с условиями. Приватный запрос позволяет указать желательные навыки и внутренние заметки; условия для кандидата оформляются в отдельном приглашении.

#### Два режима требований

| Настройка | Значение для подбора |
|---|---|
| Достаточно заявленного | Для выбранного требования подходит заявление кандидата либо соответствующее подтверждение. |
| Требуется подтверждение | Подбор проверяет действующее основание подтверждённого грейда или навыка. |
| Минимальный уровень навыка | Для поддерживаемого навыка можно задать Junior, Middle или Senior как отдельное условие. |

Режим общего грейда и требования к отдельным навыкам настраиваются раздельно. Это позволяет, например, искать заявленного Middle со строго подтверждённым SQL нужного уровня. При редактировании система учитывает версию потребности, а сохранённый отбор можно пересмотреть по обновлённым требованиям.

### 5.7. Каталог, подбор, сравнение и отдельные отборы

Рабочее пространство «Подбор специалистов» поддерживает поиск по всему доступному каталогу, по своей вакансии или по приватному запросу. Выбранное основание видно рядом с параметрами поиска.

#### Осмысленная выдача

Подбор рассматривает одно целое резюме: направление, общий грейд, обязательные навыки, отдельные уровни, условия и разрешения владельца. Один человек занимает одно место в выдаче; карточка связана с выбранным подходящим CV. Работодатель видит применимые подтверждения, условия и объяснение соответствия конкретной потребности.

Зарплатные условия сопоставляются с учётом периода и обозначения «до налогов» / «на руки». Объяснение помогает понять выполненные требования, расхождения и условия, требующие уточнения. Результаты спортивного программирования с доверенным источником представлены отдельным основанием и учитываются внутри подходящей подтверждённой категории.

#### Фильтры и порядок результатов

- Разрешённое имя или псевдоним, должность и направление, подтверждённый грейд, диапазон опыта.
- Подтверждённые и заявленные навыки - отдельными группами, с логикой «И» / «ИЛИ»; для подтверждённых можно задать уровень.
- Формат работы, локация, зарплатный диапазон, период и способ расчёта зарплаты.
- Подтверждённая история ФСП, доступное фото, готовность к предложениям, давность проверки навыков: 30, 90 или 180 дней.
- Сортировка по соответствию выбранной потребности, подтверждённому грейду, опыту, зарплатным ожиданиям, обновлению и имени; направление сортировки можно менять.

#### Сравнение и сохранение

Для сопоставления можно выбрать **от двух до четырёх специалистов** и открыть сравнение их резюме. В подборе доступны просмотр профиля, разрешённого фото и документа, добавление в отбор и подготовка приглашения.

У каждой вакансии и каждого запроса свой сохраняемый список отобранных. Работодатель добавляет и убирает людей, включает «Только отобранные», видит счётчик и возвращается к нужному списку после других переходов. Сохранение другого резюме того же человека обновляет его выбранное CV в этом отборе. При изменении требований или доступа список отражает актуальное состояние и необходимость пересмотра.

### 5.8. Приглашение с понятными условиями

Приглашение связывает **одну собственную вакансию или один приватный запрос**, конкретного кандидата и конкретное резюме. Перед отправкой работодатель проверяет основание, текст сообщения, формат работы и зарплатные условия: сумму или вилку, период и расчёт до налогов либо на руки.

Система сохраняет условия отправленного предложения и версию его основания. Это позволяет обеим сторонам возвращаться к тому, что было предложено, даже после последующего редактирования вакансии или запроса.

Кандидат видит приглашения отдельным списком, ищет и фильтрует их по статусу, резюме и формату работы. В карточке доступны сведения о компании, роли, условиях и выбранном резюме. Можно принять предложение с явным согласием на раскрытие контактов или отклонить его. Работодатель видит состояние взаимодействия и открывает контакты при действующем разрешении.

Статусы различают новое, просмотренное, принятое, отклонённое, отозванное и истёкшее приглашение. После принятия кандидат может отозвать контактное согласие; дальнейшее раскрытие через сервис определяется актуальным состоянием разрешений.

### 5.9. Видимость, согласия, фото и документы

Кандидат управляет публикацией каждого резюме. Предусмотрены скрытый, псевдонимный и публичный режимы. Разрешения на участие в подборе, включение в каталог и готовность получать предложения задаются отдельно. Для раскрытия контактов используется отдельное согласие в конкретном взаимодействии.

#### Личность и доступ

Общее фото аккаунта можно загрузить или удалить. Отображение имени и фото работодателю подчиняется выбранному режиму видимости; в псевдонимном режиме используется профессиональный псевдоним. Фильтр доступного фото и просмотр изображения также учитывают права получателя.

Сервер проверяет роль, владельца, конкретное резюме, его актуальную видимость и согласия при выдаче профиля, контактов и файлов. Кандидат может отозвать разрешение или заблокировать компанию. Решение о доступе применяется и к повторному запросу ранее сформированного документа.

#### Предпросмотр и экспорт резюме

Выбранное CV можно открыть в предпросмотре и скачать в **PDF или Word (DOCX)**. Кандидат управляет составом документа: контакты и личные ссылки, зарплатные ожидания, локация и условия, рассказ о себе, навыки, опыт, проекты, образование, портфолио и личные навыки.

Документ содержит данные именно выбранного резюме и относящиеся к нему подтверждения. Работодатель получает разрешённое представление с учётом текущего основания доступа. Предпросмотр помогает проверить содержание перед отправкой или скачиванием; встроенный просмотрщик показывает готовый PDF.

### 5.10. Задания компании и ответы кандидатов

Практика позволяет перейти от анкеты к разбору небольшой рабочей ситуации. Работодатель создаёт задание **по собственной вакансии**, задаёт проверяемую компетенцию, описание ситуации, ожидаемое время, период предложений, срок ответа и критерии с максимальными баллами.

#### Действия работодателя

Можно редактировать шаблон, приостанавливать и возобновлять его, выбирать подходящее резюме адресата и направлять задание. В рабочем пространстве видны адресаты, ответы и счётчики, доступны фильтры «Все ответы», «Новые» и «Проверены».

После получения решения работодатель оценивает его по сохранённой рубрике: указывает баллы по критериям, основания оценок и обратную связь о том, что получилось и что улучшить. Сохранённый ответ и оценка сохраняют исходный контекст вакансии и задания.

#### Действия кандидата

Кандидат открывает предложение в разделе «Практика», проверяет компанию, задание, срок и связанное резюме, принимает или отклоняет участие. После принятия он готовит и отправляет ответ, затем смотрит оценку и комментарии. Интерфейс различает предложенное, принятое, отправленное на проверку, оценённое, отозванное и истёкшее задание.

Результат практики хранится как отдельное свидетельство работы с компанией. Его публикацией и согласием на использование кандидат управляет отдельно. Квалификационные проверки Signal сохраняют собственную систему критериев и общего грейда.

### 5.11. Компания, помощь и доверие

В разделе «О компании» работодатель указывает название, предметную область, описание, рабочую почту, предпочтительный способ связи и необязательный телефон. Можно добавить ИНН организации или ИП: проверяются формат и контрольные цифры. Сведения о компании и контакты представителя используются в приглашениях. Имя аккаунта и профиль компании редактируются в предназначенных для них разделах.

Обе роли могут написать администратору: выбрать тему, описать вопрос и затем посмотреть статус обращения и ответ. Кандидат может подать обращение по компании, вакансии или приглашению, а также управлять списком заблокированных компаний.

Блокировка закрывает ранее предоставленные контакты компании и прекращает её приглашения по резюме кандидата. Разблокировка доступна в том же разделе; новое раскрытие контактов оформляется новым явным согласием.

Работодатель видит основания и сроки ограничений своей компании и может направить оспаривание. Для уполномоченного модератора реализованы очередь обращений, рассмотрение и решения с основаниями, ограничения по области и сроку, рассмотрение оспариваний, снятие ограничений и журнал действий. Роли и права отделяют эти операции от обычной работы кандидата и компании.

### 5.12. Локальный запуск и API

Поставка включает исходный код, Dockerfile, Compose, миграции базы, настройку окружения и документацию. Docker запускает приложение, PostgreSQL и Mailpit. Сборка использует закреплённые зависимости и образы; при старте автоматически применяются миграции и подготавливаются демонстрационные данные. Том PostgreSQL сохраняет пользовательские данные между остановкой и повторным запуском.

Mailpit позволяет эксперту получить код обычной регистрации прямо в локальном стенде. Интерфейс и API работают через один адрес приложения. Порты сервисов можно задать в окружении, что позволяет изолированно развернуть собственный экземпляр.

#### Программный доступ

Контракт OpenAPI 3.1 описывает запросы, ответы и ошибки. API покрывает регистрацию и сессии, аккаунты и резюме, паспорт и попытки, компанию и требования, каталог и подбор, отдельные отборы, вакансии и отклики, приглашения и контакты, задания, документы и обращения.

Персональные операции используют серверную сессию. Проверки прав выполняются на сервере, изменяющие запросы проверяют источник обращения, а версии объектов помогают согласованно сохранять параллельные изменения. Результаты проверок и отправленные условия сохраняются с их исходным контекстом.

### 7.1. Основные сущности

| Подтверждение навыка | Связь с успешно завершённой попыткой, исходными критериями, уровнем и датой. |

### 7.2. Вакансия и запрос: строгий контекст

Контекст задан парой `{type, id}`, где тип равен `job` или `need`. Одинаковые числовые ID двух типов обозначают разные объекты. Приглашение связывается **ровно с одним** основанием: `jobId XOR needId`.

Отбор уникален по компании, типу и ID основания и пользователю-кандидату. Внутри этой записи хранится выбранное резюме. Переключение CV обновляет сохранённое представление человека в одном отборе, а другие отборы продолжают работать самостоятельно.

Отправленное приглашение хранит снимок требований и фактически отправленных условий. Предложение практики хранит исходный контекст и рубрику задания. Такое разделение сохраняет смысл уже состоявшихся взаимодействий при последующем редактировании источника.

### 7.3. Подтверждения, матрица и подбор

Банк `signal-skills-2026-10-v6` выдаёт самостоятельные проверки навыков. Попытка содержит снимок заданий, правил и критериев; ключи оценки остаются на сервере. Успешное решение создаёт подтверждение навыка, связанное с аккаунтом. Матрица `signal-category-competency-matrix-v2` проверяет набор обязательных подтверждений для направления и формирует общий грейд резюме.

Подбор `fsp-signal-match-v6` сначала проверяет права и соответствие целого CV обязательным требованиям, затем формирует порядок и объяснение. Режим `declared_or_verified` принимает заявление либо подтверждение, `verified` требует действующее подтверждение; `minLevel` задаёт минимальный уровень отдельного навыка. Зарплатные периоды сопоставляются последовательно, тип расчёта gross/net остаётся явным условием.

### 7.4. Срок попытки и версии ответов

Сервер задаёт `startedAt` и `expiresAt` при выдаче попытки. Восстановление использует ту же запись и срок. Сохранение проверяет владельца, состояние, время и `revision`, чтобы новая запись не затёрла более свежие ответы из другого окна. Завершение сохраняет ответы и решение по исходной политике в одной согласованной операции. При истечении срока дальнейшая отправка закрывается; состояние отображается в истории.

### 7.5. Разрешения и защита данных

Пароли хешируются scrypt с индивидуальной солью. Сервер хранит хеш случайного сессионного токена, cookie использует HttpOnly и SameSite=Strict. Изменяющие запросы проходят проверку Origin. Доступ к каждому объекту проверяется по роли и владельцу, а к CV и документам - также по видимости, действующим согласиям и основанию взаимодействия.

Разрешения на каталог, подбор, предложения и контакты разделены. При отзыве согласия новые обращения используют актуальное правило доступа; повторная выдача документа также проходит проверку. Фото и имя следуют режиму видимости. Личные черновики разделяются по аккаунту и ресурсу, а согласованность изменений поддерживается версиями.

### 7.6. Миграции и сохранение истории

Схема PostgreSQL управляется 20 последовательными миграциями в `lib/db/migrations`. Они включают резюме, доверие и обращения, модульные проверки, аналитику CV, поиск вакансий, уровни навыков, рабочее пространство отборов и контексты заданий. Журнал применённых миграций позволяет запускать существующий экземпляр повторно.

Мягкое удаление и архивирование сохраняют связанную историю. Подтверждения аккаунта сохраняются при удалении отдельного CV. Версии программ, исходные даты и решения хранятся вместе с соответствующими попытками и снимками категорий.

Ниже приведён справочник реализованных маршрутов, сверенный с кодом сервера. Базовый путь запросов - `/api`. Для персональных операций используется сессионная cookie после входа.

Используются стандартные статусы: 400 для некорректных данных, 401 для отсутствия сессии, 403 или 404 для недоступного объекта, 409 для конфликта версии или состояния. Маршрут `/api/healthz` используется для проверки готовности приложения и Docker healthcheck. Веб-клиент, API и база разделены по ответственности, при этом единый адрес браузера упрощает запуск и сессионное взаимодействие.

### 9.2. Короткая самостоятельная проверка

1. Скачайте ZIP, создайте локальную `.env` и выполните сборку и запуск из раздела 3.
2. Проверьте `ps`, страницу приложения и `/api/healthz`.
3. Создайте два обычных аккаунта и подтвердите email через Mailpit.
4. Пройдите последовательность вакансии, CV, отклика, отдельного отбора и приглашения из раздела 4.
5. Проверьте доступ после согласия и после его отзыва, скачайте документы выбранного CV.
6. Сохраните ответы в попытке, вернитесь к матрице и продолжите до исходного срока. После отправки проверьте источник результата в паспорте.
7. Запишите видимые данные созданных объектов, остановите и повторно запустите тот же проект. Проверьте их сохранение и повторный вход.

Для полностью отдельного повторения используйте новую распакованную папку, другое имя Compose-проекта и свободные порты. Это создаёт собственный том и позволяет пройти сценарий на своей регистрации.
