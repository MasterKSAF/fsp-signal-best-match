# Резюме и документы Signal 8 октября 2026

Реализованы самостоятельный раздел «Мои резюме», отдельные серверные права предпросмотра и файлов, реальные DOCX/PDF и наблюдаемая статистика. Статус полного кабинета и независимой приёмки ведётся в общем отчёте `candidate-workspace-skill-matrix-2026-10-08.md`.

## Модель и миграция

`0011_resume_analytics.sql` добавляет `signal_resume_events` и `signal_resume_work_preferences`. Существующие резюме, имена, квалификации, попытки, даты и исторические снимки не переписываются; просмотры задним числом не создаются. Новая модель включается явно через `SIGNAL_WORKSPACE_ENABLED=true` только на отдельном стенде. При выключенном флаге прежний `/me/resumes` не запрашивает новые таблицы.

Заполнение — пять профессиональных разделов: роль/направление, описание, стек/навыки, опыт или проекты, формат работы. Фото, личные контакты и необязательное образование не входят в знаменатель. Подтверждение навыков имеет отдельный знаменатель из всех выбранных уникальных навыков; неподдерживаемые навыки остаются в нём и помечаются явно. Это не пригодность и не общий грейд. Исторические результаты не превращаются в новые индивидуальные уровни.

Несколько резюме могут быть активными; это `visibility`, а не `isPrimary`. Активация скрытого документа меняет только видимость на псевдоним и сохраняет оба согласия без изменений. Все скрытые резюме допустимы. Скопированный документ скрыт и не наследует согласия; его профессиональные условия копируются. Общая личность и конфликтная защита сохраняются в основном редакторе; отдельные условия работы также проверяют ревизию резюме.

## События

Просмотр — явный `POST /resumes/:id/view` при открытии документа работодателем. Загрузка списка, JSON preview, inline PDF preview, кандидат и запрещённые запросы не считаются. Скачивание — завершённая успешная выдача файла авторизованному работодателю (`Response.finish`). Сервер не утверждает, что файл сохранён на устройство.

Дедупликация: один аккаунт работодателя × конкретное резюме × вид события × календарные сутки UTC; PDF и DOCX делят один счётчик скачивания. Это суточное окно, не скользящие 24 часа. Карточки показывают события за последние 30 дней. Смена видимости, удаление или возврат в каталог событий не создают. Накрутка просмотров разными аккаунтами сама по себе не ограничивается этой метрикой; она не участвует в квалификации и ФСП-приоритете.

## API

Все пути ниже имеют префикс `/api`:

- `GET /me/resumes`: прежние поля плюс `completion`, `skillProgress`, `analytics`, `workPreferences`, текущая квалификация и отдельно исторические сведения.
- `PATCH /me/resumes/:id/work-preferences`: location, schedule, employment, relocation, startAvailability и обязательная revision; устаревшая ревизия даёт 409.
- `GET /resumes/:id/document-preview`: текущая серверная проекция состава документа.
- `GET /resumes/:id/preview.pdf`: встроенный просмотр без события скачивания.
- `GET /resumes/:id/document.pdf` и `/document.docx`: реальные файлы.
- `POST /resumes/:id/view`: явное событие открытия; владелец не учитывается.

Каждый запрос заново проверяет текущую сессию, роль, принадлежность к одному пулу, удаление, блокировку компании и права конкретного резюме. Владелец получает свою полную проекцию. Работодателю доступны каталог с согласием, допустимый подбор по собственной потребности либо адресное разрешение из конкретного принятого приглашения/отклика. Доступ к одному документу не перечисляет и не открывает остальные. Адресное законное разрешение сохраняется при скрытии, но отдельный отзыв закрывает все серверные URL.

Контакты разрешены только по адресному действующему разрешению для того же резюме и компании. Без него проекция удаляет контакты из свободного текста, ссылки, телефоны, email, упоминания мессенджеров и анонимные имена. DOCX/PDF строятся только из этой проекции, без скрытого owner-документа. Metadata содержит только Signal и общий заголовок; filename — технический ID документа. Все ответы `no-store, private`. Уже законно скачанный работодателем файл сервер удалённо отозвать не может.

## Интерфейс

Новый компонент `MyResumesPage` содержит создание до пяти документов, компактные карточки, два прогресса, видимость/каналы, 30-дневные счётчики, просмотр, копирование, удаление, редактирование и условия работы. Пользовательского действия «Сделать основным» нет. Скрытые редакторы остаются смонтированными в пределах раздела, чтобы смена выбранного документа не уничтожала черновик. Root-редактор использует явный ID каждого документа.

`ResumeDocumentButton` открывает единый preview для владельца и работодателя. В preview есть состав документа и настоящий PDF; Word/PDF доступны отдельными действиями. JSON, PDF и DOCX используют одинаковый порядок разделов и содержимое, хотя пагинация и шрифты разных форматов могут отличаться.

## Интеграционные исправления

У исторического Demo образование имело точность года (`2018`–`2022`). Новый список ранее падал на проверке, требовавшей обязательный месяц. Контракт образования теперь поддерживает `YYYY` и `YYYY-MM`, хранит исходную точность и не добавляет выдуманный январь. Хронология сравнивается по имеющейся точности; недопустимые месяцы и явно обратные годы по-прежнему отклоняются. DB и прошлые ответы не менялись. Старый PDF renderer также корректно отображает год без `undefined`. Подмножество из 23 проверок и API typecheck пройдены.

На пересобранном обычном API 4367 выполнен отдельный Demo HTTP smoke без reseed: login, список резюме, прямое чтение, JSON preview, inline PDF, PDF и DOCX вернули 200. Диапазон `2018 - 2022` сохранён во всех документах; DB hash образования до и после совпал. Собственная новая сессия закрыта, экзамены и содержимое резюме не записывались. `demo-year-compatibility-http.json` привязан к реально запущенному PID 21688 и bundle SHA `f523b3fc1c2faae60dddb6bd90cbcf2c1a5a61093952df9a39764f84b2e62238`. Эта квитанция относится к указанной сборке до последующего отдельного исправления rubric v2.

Реальный Demo DOCX дополнительно преобразован тем же изолированным LibreOffice в PDF: одна страница. Серверный Demo PDF: две страницы. Все три страницы просмотрены, кириллица и годы корректны, наложений и обрезки нет. `demo-year-compatibility-render.json` содержит SHA документов и результаты проверки; предыдущая квитанция 14 страниц сохранена отдельно.

Доступ к документу через подбор теперь применяет серверный sidecar минимальных уровней навыков по каждой собственной потребности. Каталог и адресное разрешение сохраняют самостоятельные правила.

Исторический helper `upgrade-owned-stage-v060.cjs` не расширен до миграций 0010–0013. Read-only `--check-only` читает новые хеши, сообщает `prepared:false` и отсутствие разрешения на старый upgrade. Любой фактический запуск legacy upgrade/capture с новым журналом прекращается до Docker/SQL; отдельный root release flag по-прежнему обязателен и сам по себе не снимает потолок 0009. Это предотвращает случайный запуск общего современного migrator на прежнем защищённом стенде.

## Независимая коррекция 02

Независимая проверка обнаружила четыре причины, не покрытые прежней квитанцией: контакт в specialization вне sections, `DENY` на разрешённом iframe PDF, маскирование годовой зарплаты как телефона и событие скачивания при HEAD. Прежний PASS не является приёмкой этих случаев.

Все пользовательские строки итоговой проекции, включая specialization и верхнее имя/псевдоним, теперь проходят одну политику контактов. Пользовательские значения не попадают в metadata. Разрешённые ссылки отдельно ограничены HTTP(S) без userinfo; без контактного разрешения hyperlinks отсутствуют. Суммы принимаются как неотрицательные безопасные целые с проверенными периодом и типом; датовые диапазоны собираются из валидированных дат. Только объекты, созданные внутренними структурированными builders, обходят распознавание телефона; произвольный флаг из содержимого не даёт такого обхода.

Только успешно разрешённый и отрендеренный inline PDF получает `X-Frame-Options: SAMEORIGIN` и `Content-Security-Policy: frame-ancestors 'self'`. Глобальный `DENY`, отказы ACL и заголовки остальных маршрутов сохранены. Событие скачивания создаётся только после успешного завершения GET; HEAD не выдаёт тело и не считается.

Regression tests покрывают 36 текстовых путей, metadata/links, четыре комбинации месячных/годовых сумм и owner/permitted сохранение specialization. 14 focused document/progress tests и API typecheck прошли. Новый `scripts/resume-documents-correction-02-http.ts` прошёл на обычной пересобранной API 4367, PID 38784, bundle SHA `8ebd0103d09728eb86071131e0c389a4b1c9ad1bf9ac6b4d6e93ad087aa99926`. Семь групп проверок включают собственные UUID-акторы, три настоящие oracle-assisted механические module submits, штатные приглашение/принятие/отзыв, A/B/owner, HEAD и заголовки, реальные файлы, дедупликацию событий и все прежние URL после отзыва. `documents/correction-02/http.json` — PASS. Четыре собственные учётные записи удалены, остаток 0; MD5 семи исходных попыток, user997 и resumes504/505 до/после совпал.

Для браузерной приёмки отдельный запуск удерживал собственные данные на двух стадиях: после принятия и после отзыва. Продолжение каждой стадии требовало отдельного явного stage; пароли и cookies хранились только в приватном manifest, затем manifest и continue удалены вместе с фикстурой. Два ранних сбоя самого QA сохранены отдельно: сериализация pypdf IndirectObject в extractor и устаревшее ожидание views1 после законного UI просмотра A (фактическое значение2). Второй случай исправлен сравнением baseline→B+1, без удаления событий или изменения аналитики.

Отдельный pure probe действительно сформировал исправленные DOCX/PDF, сохранил specialization с замаскированным контактом и суммы `1200000`–`1800000`. Word преобразован изолированным LibreOffice; обе страницы Word/PDF просмотрены. По извлечённому тексту и metadata контакта нет, годовые суммы есть; `documents/correction-02/pure-probe/render.json` содержит SHA и границы этой проверки.

Свежие реальные HTTP DOCX/PDF работодателя A с разрешёнными контактами и B без разрешения отдельно отрендерены LibreOffice/Poppler; просмотрены все семь страниц. У B контактов нет ни в тексте, ни в XML/metadata/hyperlinks; у A разрешённые контакты сохранены. Годовые суммы и `2018 - 2022` корректны, кириллица читается, наложений/обрезки нет. `documents/correction-02/http-render.json` связывает файлы, source hashes и runtime SHA. Разная пагинация Word и серверного PDF ожидаема.

Root подтвердил в живом UI две PDF страницы владельца и первую страницу A; после обычного отзыва приглашение A показывает «Кандидат отозвал доступ к контактам». Скриншоты лежат в `ui-core/correction-02-pdf-owner-page1.png`, `correction-02-pdf-owner-page2.png`, `correction-02-pdf-allowed-employer.png`, `correction-02-revoked-employer.png`. Нативный iframe PDF текущего IAB показывал пустую область при непустом корректном файле; просмотр заменён локально загружаемым PDFjs canvas с обычным запросом `preview.pdf` и повторной ACL. Прямая top-level навигация IAB к API блокируется самим браузером до серверного ответа, поэтому браузерный B404/отозванный direct-URL404 не заявляется: эти отказы подтверждены настоящим HTTP. Защитные iframe headers маршрута и глобальный DENY сохраняются независимо от выбранного renderer.
