# Работающие жалобы, блокировки и ограничения

Этап 6 октября 2026 года. Этот документ описывает реализованный контур, отдельный от архитектуры реальной юридической проверки и ATS. Подтверждённая почта не является проверкой компании.

## Согласия и блокировки

Кандидат блокирует компанию для всего аккаунта через `PUT /api/me/companies/:id/block {blocked:true}`. Компания должна быть доступна через опубликованную вакансию или собственное предложение/отклик кандидата. Блокировка запрещает новые адресные обращения ко всем резюме и доступ к контактам; существующие grants этой пары сразу отзываются в той же транзакции. `{blocked:false}` снимает запрет, но не восстанавливает grants. Повтор одинакового действия не создаёт новое событие. Чтение старой ссылки не заменяет текущую проверку разрешения.

Все действия, создающие grants, и блокировки используют одну company row lock перед проверкой и записью, чтобы запоздалое принятие приглашения не создало новое согласие после отзыва. Серверный `assertCompanyActionAllowed` учитывает личную блокировку и актуальные ограничения по действию; контакты проверяются с областью `contacts`, приглашения/предложения — `invitations`, публикация — `publishing`.

## Жалоба

`POST /api/me/complaints`: `{objectType:company|job|invitation,objectId,category,explanation?,idempotencyKey}`. Причины: spam, misleading, discrimination, inappropriate, privacy, other. Пояснение до 2000 символов, без управляющих символов; интерфейс выводит как текст. Контакты не подставляются. Доступ к конкретному объекту, роли и Demo/обычному пулу проверяется сервером. Закрытая вакансия доступна для обращения только при собственном сохранённом отклике.

Сохранение и idempotency receipt атомарны под user advisory lock. Ключ изолирован по автору; другое содержание того же ключа — 409. Одно дело на автора + тип/ID объекта + категорию; новая попытка сообщить тот же случай возвращает сохранённое дело. Лимит **10 новых дел за скользящие 24 часа** (UTC timestamps, одинаковая продолжительность во всех поясах); повтор не расходует лимит. 429 содержит `COMPLAINT_RATE_LIMIT` и `retryAt`. Ошибка транзакции не расходует лимит. Сам факт обращения не блокирует компанию и не меняет грейд/рейтинг.

Автор получает своё состояние через `GET /api/me/complaints`; чужие обращения ему недоступны. Состояния: submitted → in_review → dismissed/upheld; из submitted также можно непосредственно вынести решение. Конечное решение не переписывается: снятие ограничения и апелляция — отдельные события.

## Модератор и решение

Право хранится отдельно в `signal_moderator_permissions`. `GET /api/me/trust-status` выдаёт `{moderator:boolean}` текущему аккаунту. Регистрация/редактирование профиля не выдают это право. Назначает локальный оператор:

`node --env-file-if-exists=.env --import tsx scripts/manage-moderators.ts --user-id <id> --operator <operator-name>`

Для отзыва добавить `--revoke`. Команда проверяет существование аккаунта и добавляет событие привилегии; сам пользователь не может вызвать её через веб API. MFA/юридическая проверка не реализованы и не заявлены.

`GET /api/moderation/queue` — дела и апелляции только своего Demo/обычного пула, без контактных полей. Дела, апелляции и журнал своей компании исключаются даже у владельца с правом модератора. `POST /api/moderation/complaints/:id/decision` принимает `{action:review|dismiss|restrict,reason,scope?,durationHours?,publicReasonCode?}`. Модератор не рассматривает жалобу на свою компанию или собственное обращение. Повтор того же сохранённого решения не создаёт санкцию/аудит второй раз; изменение области, срока или публичного кода причины при повторе возвращает 409.

Ограничения имеют scope invitations / contacts / publishing / all, основание, дату, срок и ID дела. По умолчанию срок 168 часов; допустимы 1–720 часов. Они проверяются на каждом соответствующем действии и истекают автоматически по текущей дате. `contacts`/`all` отзывают ранее выданные grants компании; истечение/снятие их не восстанавливает. Ограничение invitations само по себе ограничивает новые обращения и не заменяет решение о существующих contacts. Нет санкций без решения уполномоченного модератора.

Публичная причина берётся из контролируемого кода категории, не из текста/контактов автора. `GET /api/employer/restrictions` не содержит автора, его ID, исходное объяснение или ID жалобы. Работодатель видит область, фиксированную причину, срок, состояние и собственную апелляцию.

## Апелляция и журнал

`POST /api/employer/restrictions/:id/appeals {explanation}`: только своя компания, одна неизменная апелляция на ограничение. Повтор одинакового текста возвращает прежнюю запись, другое содержание повторного обращения — 409.

`POST /api/moderation/appeals/:id/decision {action:accept|reject,reason}` рассматривает другой модератор, не автор ограничения и не владелец компании. Принятие снимает ограничение, сохраняя прежние события и отозванные grants. `POST /api/moderation/restrictions/:id/lift {reason}` позволяет явно снять ограничение уполномоченному модератору; владелец компании не снимает своё.

`signal_trust_audit` записывает фактические действия, actor, дату, объект, основание и минимальные изменения. Исходный текст жалобы и контакты туда не копируются. DB-trigger отклоняет UPDATE/DELETE; участникам нет API редактирования. `GET /api/moderation/audit` доступен модератору своего пула, до 200 последних событий. События операторского назначения роли доступны локальному оператору в БД, без публичного вывода.

Реальные внешние уведомления/ATS, проверка реквизитов, автоматический бан по проценту отказов и определение нечестности кандидата в этот контур не входят.
