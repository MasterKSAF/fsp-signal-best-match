# Browser QA — FSP SIGNAL

Проверять на `http://127.0.0.1:4310`. API — `4312`, локальная почта — `8026`.
Зафиксировать реальный результат проверки; этот файл сам по себе не означает, что сценарии пройдены.

## Подготовка

- Desktop: 1440 × 900, light и dark. Mobile: 390 × 844.
- Данные демо синтетические. Регистрация создаёт отдельные реальные аккаунты, их не должно быть в демо-подборе.
- Использовать доступные имена элементов или `data-testid`. ID кандидатов, потребностей и попыток брать с текущего экрана.
- DevTools: проверять console errors, неудачные API-запросы, горизонтальный overflow страницы. Код внутри кейса может прокручиваться отдельно.

## Вход и изоляция

1. `/auth`: `button-demo-employer` → «Кого ищем». В шапке есть метка «Демо-сценарий».
2. `button-logout` → `/auth` → `button-demo-candidate`: на экране кандидат, данные компании не остаются в кеше.
3. После выхода открыть `/candidate/passport`: показано предложение войти, без чужого профиля.
4. В роли кандидата открыть `/employer/matches`: понятное сообщение о другой роли и ссылка в свой кабинет.
5. Реальный путь: `button-switch-auth`, `input-display-name`, `input-email`, `input-password`, `checkbox-terms`, `checkbox-privacy`, `button-auth-submit`. Получить код только из Mailpit, ввести `input-verification-code`. На странице регистрации секрет не показан.

## Кандидат

1. `nav-candidate-passport`: заполнить `input-profile-name`, `input-alias`, `input-stack`, `input-skills`.
2. Ввести стек с клавиатуры через запятые, например `Python, PostgreSQL, Docker`. Запятые не исчезают во время ввода.
3. `select-assumed-grade` → Senior; `button-save-profile`. Заявленная категория меняется, подтверждённая самопроизвольно не меняется.
4. Изменить `select-visibility`, `checkbox-consent-matching`, сохранить и обновить страницу. Значения сохраняются.
5. `passport-evidence`: видно, какие навыки подтверждены, какой источник и дата. Заявленный стек показан отдельно.
6. `button-print-passport`: предпросмотр печати содержит только паспорт, без меню/форм/контактов. В браузере можно выбрать «Сохранить как PDF».
7. «История КАЛИБР»: пустое состояние для нового аккаунта; реальные дата, категория и результат для завершённых попыток; «Разбор» открывает нужный attempt.

## КАЛИБР

1. `nav-candidate-kalibr`, `select-kalibr-grade`, `button-start-assessment`.
2. Шесть кейсов: пять семейств и изменение условия. Данные варианта сохранены сервером. Не должно быть кнопок правильного заполнения.
3. В numeric/text-кейсе `input-answer-<caseId>` отображает формат ответа из условия. SQL/Python fenced snippets — моноширинные, переносы и отступы сохранены.
4. Выбрать ответы, `button-save-answers`, обновить страницу: значения восстановлены. `status-answer-save` отражает результат настоящего запроса.
5. Сменить тему во время попытки: введённые ответы остаются на месте.
6. `button-submit-assessment`: результат содержит балл и критерии; повторное открытие не создаёт новую попытку. Ошибка API видна пользователю.
7. Проверить незаполненную попытку: перед отправкой браузер спрашивает подтверждение.
8. Только серверное подтверждение нового уровня вызывает уведомление; после refresh анимация не воспроизводится снова.

## Работодатель и подбор

1. `/employer/company`: изменить название, описание, отрасль и почту. «Сохранить компанию» → успешное сообщение, refresh сохраняет значения.
2. `button-create-need`: `input-need-title`, `input-required-skills`, `input-desirable-skills`, зарплатный диапазон, описание → `button-save-need`.
3. В подборе `select-match-need` переключает потребность и очищает выбранные профили/сравнение.
4. `input-match-search`, `filter-grade`, `filter-fsp`: меняются результаты и счётчик; после refresh фильтры сохранены. Пустой результат содержит кнопку сброса.
5. `button-select-candidate-<id>` показывает нужный профиль. `/100` — базовый балл, бонус ФСП подписан отдельно как изменение порядка выдачи.
6. «Карта доказательств»: раскрытие требования показывает источник, дату, основание. «Из чего складываются … баллов» раскрывает веса и вклад факторов.
7. Два checkbox с доступным именем `Сравнить: <alias>` → `button-compare-candidates`. Третий checkbox отключён. В сравнении оба профиля и их собственные доказательства.
8. В диалоге Tab/Shift+Tab не уходят за пределы, Escape закрывает, фокус возвращается на кнопку открытия. На мобильном оба профиля доступны вертикально.

## Приглашение и контакты

1. `button-invite-<id>`: видны роль, диапазон, период, gross/net и формат; контакт кандидата отсутствует.
2. `input-invite-title`, `input-invite-message`, `input-invite-reason` → `button-send-invitation`. При ошибке диалог остаётся открыт и показывает ошибку.
3. Кандидат: `nav-candidate-invitations`, `card-invitation-<id>`. Контакт компании виден до решения.
4. `button-decline-<id>`: статус обновился, контакты остаются закрыты.
5. На другом приглашении `button-accept-<id>`: сервер подтверждает согласие; короткое уведомление воспроизводится один раз.
6. Работодатель: `nav-employer-invitations` показывает контакты только после согласия. Другая компания их не получает (это также проверяет интеграционный API-тест).
7. Кандидат: `button-revoke-contact-<id>`; после обновления у работодателя контакты недоступны.

## Качество, темы и доступность

1. `link-public-quality` на главной или «Лаборатория качества» в меню: отчёт API, реальные контрольные метрики, явная подпись о синтетической разметке команды.
2. `button-theme-menu` → `theme-light`, `theme-dark`, `theme-system`. Профиль, данные и заполненные формы сохраняются.
3. Две вкладки: смена темы в первой обновляет вторую. В режиме system смена системной темы обновляет обе вкладки. Refresh не даёт заметной вспышки другой темы.
4. `/settings`: `motion-reduced`, `motion-off`, `motion-system`. Настройка синхронизируется между вкладками; системный reduce-motion всегда учитывается.
5. Mobile: `button-mobile-menu`, закрытие кнопкой/фоном/Escape. В закрытое меню нельзя попасть клавишей Tab; открытое меню удерживает фокус.
6. Клавиатура: видимый focus ring, доступная ссылка «Перейти к содержимому», формы подписаны, масштабирование браузера не запрещено.
7. `/unknown-path`: понятный русский 404. При недоступном API — ошибка и повтор запроса, без бесконечного загрузчика.

## API-проверки

`pnpm test:integration` проверяет настоящие регистрацию/почту/сессии, КАЛИБР, подбор, согласие, изоляцию компаний и демо, просроченные/устаревшие попытки, старый обход «везде второй ответ». Тест читает oracle только из локальной БД внутри тестового процесса; публичного endpoint для этого нет. Созданные тестовые аккаунты удаляются по точно сохранённым ID в `finally`.
