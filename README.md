## Что изменилось в 0.6

- **«Мои подтверждения».** Один исходный критерий остаётся одним источником, даже если подходит пяти резюме. Видны дата, программа, версия, уровень критерия, применимые документы и причины неприменения. Отзыв прекращает все применения; удаление исходного резюме сохраняет историю.
- **Понятные категории.** Сначала соответствие потребности и полнота доказательств. Между равными категориями используется устойчивый нейтральный порядок; сведения ФСП влияют только внутри категории и не присваивают грейд. Подбор: `fsp-signal-match-v6`; каталог: `resume-catalog-v2-confirmed-first`.
- **Практика под конкретное резюме.** Компания и подписка фиксируют документ, ревизию и исходный контекст. Смена основного резюме не подменяет адресата; скрытие, удаление, смена направления или отзыв разрешения прекращают новые действия. Оценка компании остаётся `company_task`, отдельно от квалификации Signal.
- **Удобные формы.** Должность, проектная роль, предметная область и личные навыки поддерживают подсказки и собственные значения. IT-направление выбирается из поддерживаемых программ. Светлая, тёмная и системная темы; настройки движения не влияют на время экзамена.

Исторические монолитные программы: **Backend / Python** и **Frontend / TypeScript**, Junior/Middle/Senior, `signal-backend-python-v7` и `signal-frontend-typescript-v3`. Уже выданные попытки сохраняют исходную версию и правила. Новая модульная методика 0.7.0 описана выше; прежний результат не создаёт сертификаты отдельных навыков задним числом. Квалификация Signal отделена от задания работодателя и спортивного разряда.

Исправления независимого аудита 7 октября: серверный поиск и страницы получателей практики, отказ для пустых обязательных навыков, читаемое поле фотографии, объяснения сравнения по фактическим протоколам и шесть новых обзорных Demo-профилей. [Текущая приёмка 0.6.1](docs/independent-fixes-20261007.md) отделена от исторических результатов 0.6.0. [Новый контроль подбора](docs/independent-business-quality-20261007.md) и [анализ экзаменов](docs/assessment-equivalence-audit-2026-10-07.md) сохраняют ограничения синтетических проверок.

## Запуск локально

Целевая среда: Node.js 24, **pnpm 11.25.0**, Docker с Compose. Из новой локальной копии:

```powershell
node scripts/setup-env.mjs
pnpm install --frozen-lockfile
docker compose up -d db mail
pnpm db:migrate
pnpm db:seed
pnpm dev
```

Dev: веб `http://localhost:4310`, API `http://127.0.0.1:4312/api/healthz`, PostgreSQL `55433`, Mailpit `http://127.0.0.1:8026`. Seed добавляет обзорные синтетические примеры; повтор не сбрасывает рабочие записи и индивидуальные проверки. Reset не используют для получения новой попытки.

Полностью контейнерный вариант на отдельной локальной копии:

```powershell
node scripts/setup-env.mjs
docker compose --profile full up -d --build
```

Веб/API: `http://localhost:4310`, готовность — `/api/healthz`. Контейнер выполняет миграции и обзорный seed при `DEMO_MODE=true`. Для второго стенда нужны собственные порты, имя Compose-проекта и БД. `down --volumes` уничтожает данные и не применяется к рабочему стенду.

Для нового собственного экзамена, а не просмотра готового Demo, используйте [самостоятельную проверку](docs/reviewer-access.md). Рецепт создаёт отдельный стенд `4334/55441/8034` и две изолированные пары кандидат–работодатель. Доступы создаются случайно вне проекта. Рабочий веб на `4314` — другой стенд, его состояние рецепт не использует.
