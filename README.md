# Signal

Signal помогает кандидату и работодателю выбрать друг друга по навыкам и условиям. Кандидат управляет несколькими резюме, подтверждает отдельные навыки и решает, кому открыть данные. Компания ведёт вакансии и приватные запросы, сравнивает конкретные резюме и видит причины соответствия.

Решение Best Match для специального трека Федерации спортивного программирования, ЛЦТ 2026.

## Возможности

- Кандидат: резюме и экспорт PDF/Word, паспорт навыков, проверки с сохранением истории, вакансии и отклики, приглашения и управление доступом. Импорт PDF работает отдельно после настройки изолированного обработчика.
- Работодатель: вакансии и запросы, подбор с объяснением факторов, предварительный расчёт новых требований, история версий, обратная связь и подписка на новые совпадения, сравнение и совместный отбор, приглашения с бюджетом и воронкой.
- Эксперт с временным разрешением: рассмотрение обращения и отдельное решение с происхождением доказательств. Исходный ответ и оценка сохраняются.
- Опционально: подписанный публичный паспорт выбранных навыков и события ATS. Адаптивная процедура — эксперимент; исполнение Python — только в отдельной непроизводственной среде; прогноз принятия предложения недоступен.

Права привязаны к **выбранному резюме**, компании и текущим согласиям. Подтверждение навыка аккаунта не открывает остальные CV. Гостевой отбор требует отдельного разрешения. Публичный паспорт содержит выбранные подтверждения, без резюме и контактов.

## Базовый запуск Docker

Нужны Docker Engine/Compose либо Docker Desktop с Linux containers и интернет для первой сборки. Выполняйте команды из корня полученных **текущих исходников**. Свободные порты: веб `4450`, PostgreSQL `55450`, локальная почта `8050`. Node.js на хосте для этого пути не нужен.

Windows, **PowerShell 7**:

```powershell
docker run --rm -v "${PWD}:/app" -w /app node:24-bookworm-slim@sha256:0e0ff40c39bc087845bfb27465a0df4ea419520094bc35842ff83dd8cbe6f9b6 node scripts/setup-env.mjs
docker compose -p signal-local --profile full config --quiet
docker compose -p signal-local --profile full up -d --build --wait --wait-timeout 180
```

Linux/macOS, sh:

```sh
docker run --rm --user "$(id -u):$(id -g)" -v "$PWD:/app" -w /app node:24-bookworm-slim@sha256:0e0ff40c39bc087845bfb27465a0df4ea419520094bc35842ff83dd8cbe6f9b6 node scripts/setup-env.mjs
docker compose -p signal-local --profile full config --quiet
docker compose -p signal-local --profile full up -d --build --wait --wait-timeout 180
```

Откройте [Signal](http://localhost:4450), [health](http://localhost:4450/api/healthz) и [локальную почту](http://localhost:8050). Вход Demo находится в окне входа; аккаунты создаёт штатный seed. Обычная регистрация не требует старых тестовых пользователей.

`setup-env.mjs` создаёт локальную `.env` со случайными паролем БД и секретом проверки почты. Существующий файл сохраняется. Перед обновлением существующей установки следуйте [инструкции сохранения данных](docs/operations-current.md#обновление-и-откат). Не запускайте генерацию нового пароля для уже созданного volume. При конфликте портов меняйте `SIGNAL_HTTP_PORT`, `SIGNAL_DB_PORT`, `SIGNAL_MAIL_PORT`; для нативного запуска синхронно исправляйте `DATABASE_URL` и `MAILPIT_URL`. Внешний HTTPS-адрес контейнерного приложения задаётся `SIGNAL_PUBLIC_URL`.

Контейнер применяет 36 миграций `0000–0035`, запускает идемпотентный Demo seed только при `DEMO_MODE=true`, затем штатный сервер с локальными планировщиками. Повторный `up` с тем же проектом сохраняет БД. Остановка: `docker compose -p signal-local --profile full stop`. Не используйте `down -v` для установки с историей.

Базовый контейнер не получает Docker socket, ключ подписания паспортов или внешние учётные данные. PDF-импорт, публичный выпуск паспортов, SMTP и ATS настраиваются отдельно. Недоступный обработчик возвращает понятную ошибку, а не выдуманный результат.
