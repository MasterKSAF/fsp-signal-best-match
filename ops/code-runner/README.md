# Python practice runner — restricted QA experiment

Baseline Signal microtask answers are reviewed text; skill module integer/text comparison is not execution of a submitted program. This separate practice actually executes Python3.11.14, with an immutable task/test/source snapshot. It does not award skill or grade evidence.

Build locally: `docker build -t signal-code-runner:1 ops/code-runner`. Enable only on the isolated development host with `SIGNAL_CODE_RUNNER_ENABLED=true`. Production is intentionally blocked until a stronger isolation boundary (dedicated VM/gVisor/Kata and its operational review) is installed and independently accepted. A shared host kernel container does not establish a complete security boundary for hostile public workloads. The main app works with this flag off and no Docker.

The API coordinator pins the locally resolved SHA256 image ID on first execution and never silently substitutes another image on retry. The result stores that digest, Python runtime3.11.14, test version, source hash and execution fence. Image config digest identifies the exact local image even without a registry RepoDigest. Keep the pinned image while its attempts can be replayed.

Every test runs in its own nonroot container with no network, host mounts, Docker socket, API tokens or DB environment. Root FS read-only; /tmp16MiB, noexec/nosuid/nodev; memory192MiB/no swap; child address space128MiB, CPU2s, wall3s, host transport6.5s, pids16, nofile32, file1MiB, stdout/stderr8KiB. Capabilities dropped/no-new-privileges. Timeout/cancel removes the named container, which kills its process tree. No user stdout/stderr or hidden inputs/expected values are returned to UI. Expected values stay in the trusted coordinator, never in the untrusted container. The small bootstrap is readable but contains no answers.

Queue limit50; each account3 new attempts/24h; maximum2 live DB leases across workers. This implementation starts one execution per API instance. Claim uses SKIP LOCKED and a fencing token. Expired worker results cannot publish. Worker loss retains the original source and on-time submitted_at. `infrastructure_error` allows up to two explicit retries of exactly that source even after its original deadline; no silent failing grade. User cancellation invalidates the fence. Task data/accepted source/old receipts are immutable. Containers receive only source, input and version metadata.

Statuses: passed, wrong_answer, compile_error, runtime_error, time_limit, memory_limit, infrastructure_error, cancelled. The coordinator checks output equality; no passed status based on user assertions. Transport/image/worker protocol failure is infrastructure_error. A wall/CPU limit observed by the worker is time_limit. Child address-space failure is memory_limit. OOM-kill or interrupted Docker response without a trustworthy worker receipt stays infrastructure_error. Nothing is called an assessment proof.

Run boundary tests with `node --import tsx --test tests/code-runner.test.ts` after building. Run durable fencing/recovery tests only against own QA DB55480. Re-run boundary acceptance when image/worker/host runtime changes. Do not enable public production execution solely from Compose flags or these synthetic probes.
